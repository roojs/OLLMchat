# 2026-08-25 — 8.5.1 NDJSON scripts vs args

**Status:** ✔️ Json `"args"` → ANY[] bridge re-applied (user approved). Confirm NDJSON shell tests.

**Related:** [`docs/plans/8.5-rpc-drop-callparam-reply-value.md`](../plans/8.5-rpc-drop-callparam-reply-value.md)

---

## Problem

Shell rpc tests feed the daemon NDJSON. That used to look like a `param` **object**:

```json
{"id":1,"method":"RPC-Daemon.hello","*type":"Request","param":{"*type":"DaemonParams","protocol":1,"client":"test-rpc"}}
```

Scripts were rewritten to an `args` **list** (mixed types):

```json
{"id":1,"method":"RPC-Daemon.hello","*type":"Request","args":[1,"test-rpc"]}
```

```json
{"id":3,"method":"RPC-ProjectManager.activate_project","*type":"Request","args":["/tmp/proj",false]}
```

Json today can turn arrays into binary when they are **all strings** or **all objects**. A mixed list like `[1,"test-rpc"]` is neither. It tries the object-array path, asserts, and the daemon dies (SIGTRAP) after the ready line.

Ready still works:

```json
{"*type":"Notification","method":"RPC-Daemon.ready","object-type":"Daemon",...}
```

Then stderr:

```text
Json : json_array_get_object_element: assertion 'JSON_NODE_HOLDS_OBJECT ...' failed
```

This is **not** “binary RPC can’t do `args`.” Vala clients already send `args` on the bin path; those unit tests pass. Only **JSON script → binary** doesn’t understand mixed `args` lists yet.

---

## What was added (approved)

In `libocrpc/Bin/Json.vala`, member `"args"` JSON arrays encode/decode as wire **ANY[]** (`INVALID | 0x80`) with per-element `StreamValue` (string / bool / int / nested string[]). Same sketches as below — **✔️** re-applied after user approval.

Encode sketch:

```vala
if (tag_name == "args") {
	bin.write_tag(tag_name);
	bin.out_stream.put_byte((uint8) GLib.Type.INVALID | 0x80);
	// count byte(s), then for each JSON element:
	//   StreamValue.write(bin, …)  // string / bool / int / string[]
	return;
}
```

Decode sketch:

```vala
if ((type_byte & 0x7F) == GLib.Type.INVALID && (type_byte & 0x80) != 0) {
	// read count, then each element via bin_member_to_json → Json.Array
	return out_node;
}
```

(Earlier pass also wrapped File RPC handlers in `wait_scan_idle` — pre-existing race, unrelated; reverted and **not** part of this fix.)

---

## Scope note

Vala CallParam → `args` uses bin/`StreamValue`. The Json bridge above is only so NDJSON scripts can speak the same `args` shape.
