# 2026-08-25 — FIXED — 8.5.1 NDJSON scripts vs args

**Status:** ✅ FIXED — Json `"args"` → wire ANY[] via `json_array_to_bin` / ANY[] decode in `Bin.Json`. User approved and closed.

**Related:** [`docs/plans/done/RPC-8.5-rpc-drop-callparam-reply-value.md`](../../plans/done/RPC-8.5-rpc-drop-callparam-reply-value.md)

---

## Problem

Shell rpc tests feed the daemon NDJSON. That used to look like a `param` **object**:

```json
{"id":1,"method":"RPC-Daemon.hello","*type":"Request","param":{"*type":"DaemonParams","protocol":1,"client":"test-rpc"}}
```

Scripts were rewritten to an `args` **list** (mixed types):

```json
{"id":1,"method":"RPC-Daemon.hello","*type":"Request","args":[1,"test-rpc"]}
```

```json
{"id":3,"method":"RPC-ProjectManager.activate_project","*type":"Request","args":["/tmp/proj",false]}
```

Json could turn arrays into binary when they were **all strings** or **all objects**. A mixed list like `[1,"test-rpc"]` was neither → object-array path → SIGTRAP after ready.

---

## Fix

`libocrpc/Bin/Json.vala`: member `"args"` encodes/decodes as wire ANY[] (`INVALID | 0x80`) with per-element `StreamValue`. Encode lives in `json_array_to_bin`.

```vala
if (tag_name == "args") {
	this.json_array_to_bin(tag_name, items, bin, name);
	return;
}
```

T0 expect kept aligned with production:

```bash
'.method == "RPC-Daemon.ready" and .["object-type"] == "Daemon"'
```

**🚫** File `wait_scan_idle` wrappers were not part of this fix (reverted earlier).

---

## Evidence

T0 NDJSON with `"args":[1,"test-rpc"]` returns hello responses. `test-rpc` / `test-rpc-t1` OK. `test-rpc-t2` may still fail for unrelated scan/index timing — out of scope here.
