# Release 1.4.2 package builds fail after installing ocsqlite.h

**Status:** ⏳ fixes applied and locally verified; release retry pending. 2026-11-03.

## Problem

- 🔷 The v1.4.2 Debian, AppImage, Fedora, and openSUSE release jobs fail.
- 🔷 Debian and AppImage must configure the native Meson build.
- 🔷 The Fedora and openSUSE split and remote-only RPM builds must package every installed file.

## Evidence

- ℹ️ Release run: https://github.com/roojs/OLLMchat/actions/runs/41579799421
- ✔️ Debian and AppImage report that target `ocsqlite` has four outputs but only three `install_dir` entries.
- ✔️ The fourth output exists only on the non-Android target because it adds `vala_gir`.
- ✔️ Fedora and openSUSE reach the remote-only RPM file check and report `/usr/include/ocsqlite.h` as installed but unpackaged.
- ✔️ The split RPM file list already owns `ocsqlite.h`; the all-in-one `%else` list owns only `ocrpc.h`.
- ✔️ The Debian monolithic and remote-only lists likewise own only `ocrpc.h`.

## Root cause

- ✔️ The SQLite header change enabled installation of the generated header but supplied the non-Android Vala library only three install destinations for its four outputs.
- ✔️ The all-in-one Debian and RPM package lists were not extended to own the newly installed header.
- 🚫 This is not a missing SQLite development dependency; dependency installation succeeds in all four jobs.

## Proposed fix

### `libocsqlite/meson.build`

- 💩 Keep the Android three-output mapping unchanged.
- 💩 Add a fourth disabled destination to the non-Android target. The generated GIR continues to be installed by the existing custom install script.

#### Remove

```meson
    install_dir: [true, true, false],
```

#### Replace with

```meson
    install_dir: [true, true, false, false],
```

### Debian monolithic file lists

- 💩 Add `usr/include/ocsqlite.h` beside `usr/include/ocrpc.h` in both all-in-one package lists.

#### Add

```text
usr/include/ocsqlite.h
```

### `packaging/rpm/ollmchat.spec`

- 💩 Add `%{_includedir}/ocsqlite.h` to the remote-only `%files` list beside `ocrpc.h`.

#### Add

```spec
%{_includedir}/ocsqlite.h
```

## Attempts / changelog

- ✔️ Read the four failed job logs and confirmed the two failure points.
- ✔️ Added the fourth non-Android Meson output destination; `meson setup --reconfigure build` succeeds.
- ✔️ `ninja -C build libocsqlite/libocsqlite.so` succeeds, and Meson reports `ocsqlite.h` installed to `/usr/include/ocsqlite.h`.
- ✔️ Added that header to both Debian all-in-one lists and the RPM remote-only list.
- ℹ️ The complete local build later fails in the existing GIRepository 2.0 compile path; that is separate from the package failures, which stopped at Meson configure or package ownership.
