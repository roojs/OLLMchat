## Validated `llama-cli` baseline (ROCm) ✅

**🔷** Both shapes work excellently on the 26B Q4_K_M GGUF. Prefer **A** (jinja / chat template).

### A — jinja + single-turn (preferred)

```bash
llama-cli \
  -m /home/alan/.local/share/ollmchat/models/unsloth/gemma-4-26B-A4B-it-GGUF/gemma-4-26B-A4B-it-UD-Q4_K_M.gguf \
  --n-gpu-layers 99 \
  --ctx-size 8192 \
  -n 1024 \
  --jinja \
  --single-turn \
  --color off \
  -p "Explain the benefits of unified memory in local AI."
```

### B — manual instruction wrap (no jinja)

```bash
llama-cli \
  -m /home/alan/.local/share/ollmchat/models/unsloth/gemma-4-26B-A4B-it-GGUF/gemma-4-26B-A4B-it-UD-Q4_K_M.gguf \
  --n-gpu-layers 99 \
  --ctx-size 8192 \
  -n 1024 \
  --color off \
  -p "### Instruction:\nExplain the benefits of unified memory in local AI.\n\n### Response:\n"
```

- **🔷** CLI → library map:
  - `-m …UD-Q4_K_M.gguf` → resolve real `*.gguf` under model dir
  - `--n-gpu-layers 99` → `n_gpu_layers = -1` when `supports_gpu_offload()`
  - `--ctx-size 8192` → `Call.Options.num_ctx = 8192`
  - `-n 1024` → `max_tokens` / `num_predict = 1024`
  - `--jinja --single-turn` → `model.chat_template()` + `Llama.apply_chat_template(..., add_ass=true)`
  - plain `-p` without jinja → avoid for chat models; path B only as fallback
  - `--color off` → N/A (library has no ANSI)
