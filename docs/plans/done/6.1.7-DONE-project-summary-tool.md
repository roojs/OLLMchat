# 6.1.7 Project summary via `codebase_search`

Status: DONE

ℹ️ Checklist: `docs/guide-to-writing-plans.md` — Checklist for plans.  
ℹ️ Parent: [6.1.2](6.1.2-DONE-pi-like-agent.md) (former Phase 7).  
ℹ️ Landed: `liboctools/CodebaseSearch/{Tool,Request}.vala`, `ollmfilesd/Codebase.vala` (`element_type = "project"` early exit).  
ℹ️ Indexed summary: `vector_metadata` / `Folder.project_description()` / `ProjectAnalysis`.

## Purpose

- ✅ Extend **`codebase_search`** so **`element_type = "project"`** returns the vector **project summary** on demand.
- ✅ Update tool **description** + **parameter definition** so the model knows `"project"` is valid and when to use it.
- ✅ Schema: mark `query` **`[optional]`** (drop JSON-schema required). Prose: query is **mandatory except** when `element_type` is `"project"`.
- ✅ Fix the stale description claim that docs/markdown are not searchable (`document` / `section` + `category` already work).
- ✅ Daemon **`Codebase.search`** must special-case that filter (project rows are not FAISS-searchable today).
- 🔷 AGENTS.md inject stays the always-on contract when present; the indexed **project summary** is a detailed overview (structure, languages, purpose) — fetch with `"project"`; **mandatory** when starting work on a project.
- ℹ️ Same tool path serves Agent Pi and other agents that already have `codebase_search` — no new tool name.

---

## Why a special case (not a plain filter)

- ℹ️ `ProjectAnalysis` stores the summary with `element_type = "project"`, `file_id = root_folder.id`, **`vector_id = 0`** — not embedded in FAISS.
- ℹ️ `Codebase.search` builds `file_id IN (get_ids(...))` from text **files** only; the project root folder id is not in that list.
- 🔷 Therefore `"project"` cannot ride the existing filter → FAISS path; reply with `project.project_description()` and return.

---

## Suggested order

1. ✅ Tool description + `parameter_description` (`[optional]` query; prose mandatory-except-project).
2. ✅ Request allowlist + empty-query guard for `"project"`.
3. ✅ Daemon early exit (`ollmfilesd/Codebase.vala` `search`).

## Daemon query support

### 5. `ollmfilesd/Codebase.vala` — `search`: early exit for `element_type == "project"`

**Why:** Project summary is SQL text with `vector_id = 0`; FAISS + `get_ids` cannot return it.

**Where:** `private async void search` — immediately after the `project == null` error reply block, before `load_files_from_db` / `get_ids`.

**Depends on:** none (tool allowlist can land in any order; both needed for end-to-end).

#### Add — After the `project == null` reply/`return`, before `if (project.project_files.get_n_items() == 0)`. When normalized `element_type` is `"project"`, reply with `project.project_description()` (or a short empty message) and return — skip filter/FAISS.

```vala
			if (p.element_type.strip().down() == "project") {
				var description = project.project_description();
				if (description == "") {
					request.reply(new OLLMrpc.Response() {
						id = request.id,
						msg = "No project summary is indexed yet for this project."
					});
					return;
				}
				request.reply(new OLLMrpc.Response() {
					id = request.id,
					msg = "## Project summary\n\n" + description
				});
				return;
			}
```
