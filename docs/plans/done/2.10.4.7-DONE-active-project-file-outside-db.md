---

## Purpose

- 🔷 Drop **active project** and **active file** as **daemon / SQLite** concerns.
- 🔷 Frontend owns which project / file / agent a window shows.
- 🔷 Persist that in **Config2** via a new **`Window`** settings class (not on `AgentConfig`).
- 🔷 Design the map for **multi-window** now (keyed window ids → per-window config), even though only **one** window exists today.
- 🔷 Immediate safety: **stop sending `File.activate`**; daemon must **`reply_error` on failed dispatch** (Phase 0).

---

## Why now

- ℹ️ Daemon log: `File.activate` → CRITICAL `no signal call_activate` → **no reply** → RPC queue stall → unexpected response id abort.
- 🔷 Product already wanted activation **off the backend** (this file’s earlier FUTURE text).
- 🔷 Multi-window will need **per-window** project / file / agent — one global daemon `active_*` cannot work.

---

## Target model

### Runtime (unchanged shape)

- 🔷 Each GTK window keeps a `ProjectManager` with in-memory `active_project` / `active_file` for tools and UI.
- 🔷 Daemon owns files, folders, scan, index, disk I/O — **not** “what the user is looking at”.

### Persistence (Config2)

- 🔷 New serializable class **`OLLMchat.Settings.Window`** (name approved by user).
- 🔷 `Config2` holds a map of window id → `Window`.
- 🔷 Map keys are a **UUID string** per window (`GLib.Uuid.string_random()` — same pattern as CLI tool call ids).
- 🔷 Today: **one** entry (single window still gets a UUID).
- 🔷 Later: one key per open window.

| Field on `Window` | Meaning |
| ----------------- | ------- |
| 🔷 `project` (path string) | Open project path for this window |
| 🔷 `file` (path string) | Open file path (empty = none) |
| 🔷 `agent` (factory id string) | Agent in use (e.g. `agent-pi`, `just-ask`) |

💩 Exact JSON property names (`project` / `file` / `agent` vs `project_path` / `file_path` / `agent_name`) — prefer short names matching user wording unless review wants `_path` suffix for clarity.

🔷 Window map key: assign `GLib.Uuid.string_random()` when the GTK window is first created; keep that string on the window and in `Config2.windows` for the life of that windows map entry (survives restarts for that row).

🚫 Do not use `Gtk.ApplicationWindow.get_id()` as the persisted key (process-local only).  
🚫 Do not use ephemeral Gtk widget pointers as persisted keys.  
🚫 Do not use a fixed label key like `"main"`.

### JSON sketch

```json
"windows": {
  "a3f1c9e2-b8d0-4f6a-9c1e-2d4b6a8c0e1f": {
    "project": "/home/alan/gitlive/OLLMchat",
    "file": "/home/alan/gitlive/OLLMchat/docs/plans/APP-6.2-speech-to-text.md",
    "agent": "agent-pi"
  }
}
```

## Phases

### Phase 0 — Stop the crash / stop dead RPC ✔️ 🔷

**Goal:** No more `File.activate` on the wire; unknown/missing `call_*` must reply with an error (never hang silently).

ℹ️ Crash evidence: [`docs/bugs/done/2026-08-06-FIXED-rpc-unexpected-response-id-aborts-app.md`](../../bugs/done/2026-08-06-FIXED-rpc-unexpected-response-id-aborts-app.md).

🚫 Phase 0 does **not** invent Config2 `Window` persistence — that is Phase 1+.  
🚫 Do **not** “fix” the abort by moving call timeouts, softening `GLib.error` on unexpected response ids, or other client timeout/queue cosmetics — those paper over missing replies. Cause fixes only: **0.1** + **0.2**.

#### 0.2 `libocrpc/Transport/Connection.vala` — `on_input_ready`: reply on failed dispatch ✔️

**Why:** Any unknown/missing `call_*` must not leave the client waiting until timeout.

**Where:** after `request.dispatch();` in the read loop.


### Phase 2 — Single-window restore / save ✔️ 🔷

ℹ️ Session JSON `project_path` stays for chat history (`session_selection` may still activate that path). Config2 is the source of truth for “what was open” across app restarts.

🚫 Do not put open project/file on `AgentConfig`.  
🚫 Do not add debounce.  
🚫 Do not invent a second window-id scheme (UUID only).

### Phase 3 — Daemon slim (activation) ✔️ 🔷

**Goal:** Daemon no longer persists or restores UI “active” via SQLite `is_active`. RPC that opens a project path still runs **scan / load / vector queue**; client Config2 owns what the window shows (Phase 2).

#### Design (confirm before code)

- 🔷 Stop writing / reading SQLite `is_active` for UI restore (Purpose).
- 💩 Keep wire method name `ProjectManager.activate_project` this phase — still means “daemon working project + scan/index for this path”. Rename (e.g. `open_project`) deferred unless user wants it here (was open question 3).
- 💩 Keep `filebase.is_active` column in schema unused (no migration). Drop column later if wanted.
- 🔷 Client keeps **in-memory** `Folder`/`File.is_active` for tree/UI highlight (`FileDropdown` bind) — not daemon DB.
- 💩 Daemon keeps in-memory `active_project` pointer for `vector_scan.queue_project` / scan coordination — not multi-window UI state.
- 🚫 Do not reintroduce `File.activate` RPC.
- 🚫 Do not delete client `activate_file` / local `is_active` toggles (UI).
- 🚫 Do not add `window_id` on daemon RPCs (Phase 4 / multi-window is client-only).
