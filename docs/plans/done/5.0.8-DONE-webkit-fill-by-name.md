## Purpose

- **🔷** Redesign **`fill`** so keys are **form field names**, not ephemeral **press-ref ids**.
- **🔷** Dump markdown must **show those keys** so the model can copy them.
- **🔷** Lock **dump shape** + **tool wire** first (this doc); then implement.
- **🚫** No DOM / page-JS for dump or fill (parent **5.0** veto).

---

## 1 — Current dump (v1)

Editable fields are **pressables** today. Same `(^press:N)` as buttons/links. Current value (if Text exposes it) is appended as `= value`.

```markdown
# Page
- URL: https://www.google.com/…
- Title: Google

## Content
[Search](^press:12){400,120}
[Google Search](^press:15){520,120}

## References
(^press:12): [searchbox] Search
(^press:15): [button] Google Search
```

With typed text already in the box:

```markdown
## Content
[Search](^press:12){400,120} = webkitgtk

## References
(^press:12): [searchbox] Search = webkitgtk
(^press:15): [button] Google Search
```

**How the LLM fills today** — keys are press-ref **ids** (brittle; change every dump):

```json
{
  "action": "press",
  "press": 15,
  "fill": { "12": "webkitgtk at-spi" }
}
```

- **ℹ️** Order: apply `fill`, then press `15`, settle, return new a11y dump.
- **ℹ️** Tool docs say keys are press-ref ids, **not** HTML `name` attributes.

## 2 — Proposed dump (form / fillable)

- **🔷** Keep `(^press:N)` for **activate** (buttons, links, …).
- **🔷** Editables use **`(^fill:KEY)`** where KEY = HTML `name=` (attr `"name"`), else `"id"`.

### Proposed Content / References (home search box)

```markdown
# Page
- URL: https://www.google.com/…
- Title: Google

## Content
[Search](^fill:q){400,120}
[Google Search](^press:15){520,120}

## References
(^fill:q): [searchbox] Search
(^press:15): [button] Google Search
```

With current value:

```markdown
## Content
[Search](^fill:q){400,120} = webkitgtk

## References
(^fill:q): [searchbox] Search = webkitgtk
(^press:15): [button] Google Search
```

### Marker rules (locked)

| Kind | Content | References |
| ---- | ------- | ---------- |
| Fillable (has `name` or `id`) | `[label](^fill:KEY){x,y}` optional `= value` | `(^fill:KEY): [role] label` optional `= value` |
| Pressable only (button / link / …) | `[label](^press:N){x,y}` | `(^press:N): …` (unchanged) |
| Both? | **💩** Prefer **fill-only** on editables (submit is a separate button). Or both `^fill` + `^press` if we still need press-on-field. |

- **✅** **🔷** `(^fill:KEY)` marker form locked (parallel to `(^press:N)`).

### What is `KEY`? — **locked: HTML `name=`** (attr `"name"`)

- **🔷** Fill key = AT-SPI object attribute **`"name"`** (HTML form `name=`), **not** accessible label.
- **🔷** Dump marker: `(^fill:q)` when `attrs.get("name") == "q"`.
- **🚫** Do not use accessible label as KEY.

#### Platform feasibility (2026-07-25)

| Platform | `"name"` (HTML `name=`) | `"id"` | `"tag"` |
| -------- | ----------------------- | ------ | ------- |
| **Windows** (`webview2-gtk`) | **✅** IA2 `html-input-name` → attr `"name"` | **✅** AutomationId | **✅** |
| **Android** (`webkitgtk-android`) | **✅** AssistStructure → attr `"name"` | **✅** | **✅** |
| **Linux** (stock WebKitGTK) | **⏳** still missing upstream | **✅** | **✅** |

Engine plans (done):

- Windows: [`webview2-gtk` 1.2](file:///home/alan/git/webview2-gtk/docs/plans/1.2-a11y-html-name-attribute.md) **DONE**
- Android: [`webkitgtk-android` 1.3](file:///home/alan/git/webkitgtk-android/docs/plans/1.3-a11y-html-name-attribute.md) **DONE**

- **🔷** Prefer **`name`**; fall back **`id`** when `name` empty; omit fill marker if both missing.
- **ℹ️** Google search often `name="q"` — works on Windows/Android now; Linux still needs upstream WebKit `"name"` or id fallback only.
- **🚫** DOM/JS to invent `name` — parent **5.0** veto.
- **🚫** Accessible label as KEY.

## 3 — How the LLM sends `fill`

Still an **argument** on `action: press` (not a separate action), unless we reopen that.

### Proposed tool call

```json
{
  "action": "press",
  "press": 15,
  "fill": { "q": "webkitgtk at-spi" }
}
```

- **🔷** `fill` keys copy **`KEY` from `(^fill:KEY)`** (HTML `name=` / fallback `id`), not press ids.
- **🔷** `press` still the control to **activate** after typing (Search button, Submit, …).
- **🔷** Order unchanged: fill all map entries → press → settle → dump.

### Multi-field example (login-ish)

Dump:

```markdown
## Content
[Email](^fill:email){80,200}
[Password](^fill:password){80,240}
[Sign in](^press:40){80,280}

## References
(^fill:email): [entry] Email
(^fill:password): [password text] Password
(^press:40): [button] Sign in
```

Call:

```json
{
  "action": "press",
  "press": 40,
  "fill": {
    "email": "user@example.com",
    "password": "secret"
  }
}
```

### Wire / docs deltas (after lock)

- **⏳** **🔷** `Tool.parameter_description` — `fill` keys = fill keys from dump, not press-ref ids.
- **⏳** **🔷** `A11y.fill` — resolve via fill-route map (label/name), not `press_routes` only.
- **🚫** **🔷** No transition alias for old numeric press-ref fill keys — once dump shows `^fill:`, `fill` keys are only those KEYs (not `"12"`).
