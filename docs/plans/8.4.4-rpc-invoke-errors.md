## Purpose

- **🔷** `⏳` When `fn.invoke` throws, that error must reach the client. Not a canned JSON-RPC string.
- **🔷** `⏳` `reply_error` today is only a code (`INTERNAL_ERROR` / `INVALID_PARAMS`). The message is `((RpcErrorCode) code).message` — the thrown `GLib.Error` is dropped.
- **🔷** `⏳` GI callers write `throws GLib.Error` (and catch `GLib.FileError`, `GLib.IOError`, …). The client must **emit / throw that same type**, not a generic `IOError.FAILED`.
- **ℹ️** [`8.4.2`](8.4.2-DONE-rpc-ffi-typelib-invoke.md) / [`8.4.3`](8.4.3-DONE-rpc-ffi-typelib-method.md) catch invoke with `reply_error(INTERNAL_ERROR)`. This plan replaces that path. No fences until the wire fields and client throw shape are confirmed.

---

## Today

- **ℹ️** `Connection.reply_error(request, code)` → `RpcErrorCode.to_response(code)` → wire `{ code, message }` where `message` is the JSON-RPC label (`"Internal error"`).
- **ℹ️** `OLLMrpc.Error` has `code` (JSON-RPC number) and `message`. No GError domain. No GError code.
- **ℹ️** `Client.call` returns `Response`. If `response.error != null` it logs, fires `failed(request, error)`, and still returns the response. It does not throw.
- **ℹ️** gnome-shell-rpc `Session.call` throws `GLib.IOError.FAILED(response.error.message)` — domain and GError code are gone.

---

## Wire

JSON-RPC `code` stays the envelope (`INTERNAL_ERROR` when invoke failed). The **thrown** error is extra fields on `OLLMrpc.Error`.

- **🔷** `⏳` Send the thrown **message** (what `e.message` was on the server).
- **🔷** `⏳` Send enough identity for the client to rebuild `GLib.Error` (`domain` + GError `code`) so `catch (GLib.FileError e)` still matches.
- **💩** `⏳` Properties on `Error` (names to confirm):
  - `domain` — quark string (`GLib.Quark.to_string(e.domain)`), omit when empty.
  - GError code — not `Error.code` (that is JSON-RPC). A second int, omit when `domain` is empty.
- **💩** Empty `domain` means a plain RPC error (`INVALID_PARAMS`, `METHOD_NOT_FOUND`). Client behaviour stays as today.

No protocol version bump.

---

## Server

- **🔷** `⏳` In `dispatch_new` / `dispatch_function`, the `catch (GLib.Error e)` around `fn.invoke` replies with that error, not `reply_error(INTERNAL_ERROR)` alone.
- **ℹ️** Two throws show up as `GLib.Error`:
  - `GI.InvokeError` — symbol / argument mismatch (FFI failed). Envelope `INTERNAL_ERROR` or `INVALID_PARAMS`.
  - Function `THROWS` — the C API’s own domain (`g-file-error-quark`, mutter, …). That is what the stub `throws` clause is for.
- **💩** `⏳` Grow `reply_error` so it can take the thrown error (message + domain + GError code), rather than a new helper. ollmfilesd already does `new Error(INTERNAL_ERROR, e.message)` by hand in places.

No fences until the `Error` field names and `reply_error` signature are confirmed.

---

## Client

- **🔷** `⏳` When the reply carries a domain, rebuild `GLib.Error` and **emit / throw** it so GI stubs can `catch` the type they declared.
- **💩** `Client.call` today never throws. Changing that is a break for ollmfilesd (`if (resp.error != null)`). Options (pick one):
  - Keep `call()` returning `Response`. Reconstruct `GLib.Error` on `failed`, or a property on `Response` / `Error`. GI Runtime / `Session.call` throws that error.
  - `call()` throws when `domain` is set; RPC-only errors stay on `Response.error`.
- **💩** Reconstruction: `GLib.Quark.from_string(domain)` + GError code + message (`GLib.Error.literal` or equivalent). Unknown quark → still throw `GLib.Error` with that message, do not collapse to `IOError.FAILED`.

---

## Smoke

- **💩** `⏳` After [`8.4.3`](8.4.3-DONE-rpc-ffi-typelib-method.md) `Gio-Menu.get_n_items`: one invoke that `THROWS` (a missing file, or similar) → client sees the **GFile** / **GIO** domain, not `"Internal error"`.
- **💩** Plain `INVALID_PARAMS` (bad `lease_id`) stays a JSON-RPC error with empty `domain`.
