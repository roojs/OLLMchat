## Purpose

- **🔷** `⏳` The **command string** is the dominant thing on screen (permission row and live run frame). Bold. Largest type in that widget.
- **🔷** `⏳` Repeated sudo typing for sysadmin work is too noisy. After a password has been stored, **hold** a button for **two seconds** (not a single click) to reuse it.
- **🔷** `⏳` Store that password with **libsecret** (same pattern as RooTerm, not a click-to-fill convenience button).
- **🔷** `⏳` Long runs belong in a **VTE** inside a chat frame, with a **Stop** control.
- **🔷** `⏳` Stop killing the process when output is long. Let the command finish. The LLM (and the persisted results frame) see the **last** slice of output, not the first, and not a killed process.
- **🔷** `⏳` Stuck runs (SSH sitting on a password prompt, no TTY, never exits) hit a **default wall-clock timeout**. The model can raise it per call.
- **🔷** `✔️` Short-term: tool prompt forbids `#` comments in the command string (those prompts are always denied). `liboctools/RunCommand/Tool.vala` description + `@param command`.
- **ℹ️** GTK Linux app is the target. Current kill-at-N lives in `liboctools/RunCommand/Request.vala` (`50` lines) and `libocbwrap/Bubble.vala` (`100` lines). There is **no** command timeout in the tool today.

**Suggested order:** Phase 1 (bold command) → Phase 2 (libsecret + hold) → Phase 3 (no-kill last slice + timeout + VTE + Stop). Prompt comment ban is already in the tool description.

---

## Current behaviour

- **ℹ️** Permission copy is one `Gtk.Label` (`ChatPermission.question_label`). No markup. The command is a trailing `Command: …` line under a wall of warning text.
- **ℹ️** The “running” UI fence already puts the command in the frame **title** (`Request.execute`). Title markup is `<b>` in `MarkdownGtk.RenderSourceView`, but it is the same size as every other frame title and shares the row with “Running command in sandbox”.
- **ℹ️** Root runs: type password every time → `sudo -S true` check → pipe into `sudo -S /bin/sh -c …`. Copy says the password is not saved. See `ChatPermission.vala`, `Request.execute_with_subprocess()`.
- **ℹ️** Output: `Request.read_stream_async` kills the process group at **50** lines. `Bubble.read_from_channel` sets `output_killed` at **100** lines and stops accumulating. LLM gets a head slice plus “command killed”.
- **ℹ️** No wall-clock timeout. A command that blocks on a password (SSH, `sudo` without `run_as_root`, `read`) waits until the user kills the app or the model’s turn is cancelled.
- **ℹ️** `ChatView.add_widget_frame(Gtk.Frame)` already exists and is unused. No VTE in this repo.

## Phase 1 — Bold command

- **🔷** `⏳` Permission row: the command is its own label, **bold**, and visually larger than the warning / question text.
- **🔷** `⏳` Live run frame (Phase 3): same rule — command is the header, bold, largest type in that frame.
- **💩** `⏳` CSS class `.command-preview` on both widgets (`font-weight: bold; font-size: 1.25em;` or `title-2`). Confirm size.
- **💩** `⏳` Keep the existing warning paragraphs in `question_label` **without** repeating `Command: …` there. Pass the command in as a separate string from `Tools.Permission.request_user` (the `Request` already has `command`).
- **💩** `⏳` Ellipsize the command label with a tooltip of the full string when it is long. Confirm.

## Phase 2 — libsecret + hold two seconds

- **🔷** `⏳` First successful sudo password is stored in libsecret.
- **🔷** `⏳` Later root prompts: **hold** the allow control for **two seconds**. Background fill animates while held. Release early cancels. A single click must not approve.
- **🔷** `⏳` Deny stays a normal click.
- **ℹ️** RooTerm fill: `Gtk.Overlay` child is a box whose `width_request` grows; CSS paints `.host-tab-close-fill`. Copy that overlay-on-the-button idea, do not import RooTerm widgets.
- **ℹ️** RooTerm secret: `Secret.Schema` + `Secret.password_store.begin` / `Secret.password_lookup_sync`. Inline the same calls in `ChatPermission` (no secret-helper class).

**When a secret exists**

- **🔷** `⏳` Hide the password entry.
- **🔷** `⏳` Allow (root) becomes a hold target. Label along the lines of `Hold 2s — use saved password`.
- **💩** `⏳` A small `Use a different password` control that reveals the entry and restores click-Allow (typed password overwrites the secret on success). Confirm.

**When no secret exists**

- **🔷** `⏳` Keep today’s type-then-Allow path (`sudo -S true` before resume).
- **🔷** `⏳` On success, `Secret.password_store` the password, then proceed as now.

**Wrong stored password**

- **🔷** `⏳` `sudo -S true` still runs after a completed hold (same check as typed).
- **🔷** `⏳` Failure: show the entry, error label, delete the bad secret, do **not** resume.

**Schema (confirm)**

- **💩** `⏳` Schema `org.roojs.ollmchat.Elevation`, attribute `user` = `GLib.Environment.get_user_name()`, label `OLLMchat sudo`. One secret per login user.

**Build**

- **🔷** `⏳` `dependency('libsecret-1')` on `libollmchatgtk` (Linux GTK). `--pkg=libsecret-1`.
- **🔷** `⏳` `debian/control` Build-Depends: `libsecret-1-dev`.
- **ℹ️** Android / Windows: no libsecret in v1. Root elevation is already Linux-only.

### 5. `libollmchatgtk/ChatPermission.vala` — hold fill on Allow when a secret exists

**Why:** Friction is the hold, not a second click.

**Where:** `construct` (overlay around `allow_once_btn`); `request()` when `high_risk`; press/release controllers. **Inline** — no `start_hold()` / `on_hold_tick()` helpers.

- **🔷** `⏳` Released or leave before 2000: remove timeout, `fill.width_request = 1`, `visible = false`.
- **🔷** `⏳` While holding, do **not** fire the existing `clicked` handler on Allow.
- **ℹ️** Match RooTerm tick math in `Host/TabBar.vala` (`width_request = (row.get_width() * left) / total`) — here fill **grows** with elapsed, it does not shrink.

## Phase 3 — Last slice, timeout, VTE frame, Stop

### 3a. Stop chopping / killing

- **🔷** `⏳` Do **not** kill the process because stdout is long. Remove `output_killed` kill paths in `Request.read_stream_async` and `Bubble.read_from_channel`.
- **🔷** `⏳` Let the command complete (or until the user hits **Stop**).
- **🔷** `⏳` What goes back to the LLM (and the persisted “Execution results” fence) is the **last** slice, not the first.
- **💩** `⏳` Slice size **50 lines** (today’s subprocess cap). Unify Bubble’s 100 with that. Confirm.
- **💩** `⏳` If truncated, prefix a one-line note: showing last N of total, output was longer. Confirm wording.
- **🔷** `⏳` Update `Tool.description` Output bullet: drop “the command is killed”. Say the model sees the tail.

### 3c. Default timeout + LLM `timeout` argument

- **🔷** `⏳` Every `run_command` has a wall-clock timeout. When it fires, kill the process group (same as **Stop**) and return the tail plus a clear timed-out line so the model can retry with a larger `timeout`.
- **🔷** `⏳` Tool argument **`timeout`** (seconds, integer). Document in `Tool.description` and `Tool.parameter_description`. Tell the model: raise it for installs, builds, and anything expected to run longer than the default. Example: SSH that might wait on a password still dies at the default unless they meant it to run that long.
- **💩** `⏳` Default **60** seconds when the argument is omitted. Confirm. Long `apt` / `make` is the model’s job to raise, not a 10-minute default that leaves a hung SSH sitting there.
- **💩** `⏳` Reject `timeout <= 0` with `ERROR:` (no infinite hang). Confirm vs `0` = wait until Stop.
- **🔷** `⏳` User **Stop** still works before the timer. Timer is the backstop when nobody is watching.
- **ℹ️** This is elapsed time from spawn, not idle-time. A quiet `sleep 90` with default 60 is killed. A chatty `apt` with `timeout: 600` is not.

### 3b. VTE in a chat frame + Stop

- **🔷** `⏳` GTK app: each `run_command` run gets a `Gtk.Frame` in the chat with VTE, the bold command header, and **Stop** while the child is alive.
- **🔷** `⏳` Stop kills the process (process group, same `Posix.kill(-pid, KILL)` idea as today’s kill path) and finishes the tool with whatever output exists, plus a clear “stopped by user” line to the model.
- **ℹ️** Hook already in tree: `ChatView.add_widget_frame`. Live widget. History restore will not resurrect VTE — persist the tail as the existing results fence.
- **💩** `⏳` Always VTE in the GTK app (short commands just exit quickly). One path. Confirm vs “only after N seconds”.
- **💩** `⏳` New widget file `libollmchatgtk/CommandFrame.vala` (user asked for a VTE frame; this is that widget, not a helper extracted from `Request`). Header = Phase 1 command label. Body = `Vte.Terminal`. Stop button in the header.
- **💩** `⏳` Spawn into the VTE PTY (`Vte.Terminal.spawn_async`, RooTerm `Local.spawn`) using the same argv Bubble / sudo already builds, so progress bars and `\r` work. Confirm vs pipe-and-`feed()` (no TTY).
- **💩** `⏳` bwrap: `overlay.create()`, spawn `bwrap …` argv on the VTE, on `child_exited` run overlay `scan` + `cleanup` as `Bubble.exec` does today. Seccomp `child_setup` must still run on the spawned child. Confirm this stays in `Bubble` vs moving spawn into `CommandFrame`.
- **ℹ️** CLI / Windows / Android: no VTE. Still no-kill + last-slice (3a). Root remains Linux GTK.

**Wiring (confirm)**

- **💩** `⏳` `OLLMchatGtk.Tools.Permission` already holds `ChatWidget`. Easiest: a method on `ChatWidget` that `add_widget_frame`s a `CommandFrame`, spawns, yields until exit/stop, returns the tail string. `RunCommand.Request` cannot link VTE if `liboctools` stays free of vte — so the GTK path needs a provider/callback on `Manager` (same idea as `permission_provider`). Confirm before inventing a second provider type.
- **💩** `⏳` While VTE is live, skip the current “Running command …” markdown fence (the frame **is** that UI). Still `add_message` the results fence with the tail when done, so replay works.

### 8. `liboctools/RunCommand/Request.vala` — `read_stream_async`: never kill on line count; keep a tail

**Why:** Killing was the wrong answer to long output.

**Where:** the `if (this.output_lines >= 50)` block inside `read_stream_async`.

**Depends on:** none (can land before VTE).

#### Remove

```vala
				if (this.output_lines >= 50) {
					this.output_killed = true;
					GLib.debug("command killed: output exceeded 50 lines");
					var id = subprocess.get_identifier();
					if (id != null) {
						Posix.kill(-(int.parse(id)), Posix.Signal.KILL);
					}
					subprocess.force_exit();
					break;
				}
				this.output_lines++;

				if (output != "") {
					output += "\n";
				}
				output += line;
```

#### Replace with — accumulate; tail is applied once at return (see next hunk). Keep reading to EOF.

```vala
				if (output != "") {
					output += "\n";
				}
				output += line;
```

Then at the **end** of `execute_with_subprocess` / `execute_tool_async`, take the last 50 lines of `output_content` (and of Bubble’s `result`) instead of `truncate_output(…)` which currently keeps the **first** 50.

#### Remove — `truncate_output` head slice

```vala
			var truncated_lines = lines[0:max_lines];
			var truncated = string.joinv("\n", truncated_lines);
			
			// Add truncation message (similar to codesearch tool format)
			return truncated + "\n\n// ... (output truncated: showing first " + max_lines.to_string() + " of " + total_lines.to_string() + " lines, output too long) ...";
```

#### Replace with — last slice

```vala
			var start = total_lines - max_lines;
			var truncated_lines = lines[start:total_lines];
			var truncated = string.joinv("\n", truncated_lines);
			return "// ... (output truncated: showing last " + max_lines.to_string() + " of " + total_lines.to_string() + " lines) ...\n" + truncated;
```

### 11. `liboctools/RunCommand/Request.vala` — `timeout` property + kill on expiry

**Why:** Hung interactive prompts must not block the agent forever. The model can raise the cap for real long jobs.

**Where:** property next to `allow_write`; after spawn in `execute_with_subprocess` / VTE path, arm `GLib.Timeout.add_seconds`. **Inline** — no `arm_timeout()` helper.

**Depends on:** §8 kill path reused for Stop and timeout.

#### Add — property next to `allow_write`

```vala
		/**
		 * Wall-clock seconds before the child is killed. Omitted JSON uses 60.
		 */
		public int timeout { get; set; default = 60; }
```

- **🔷** `⏳` After spawn: `GLib.Timeout.add_seconds(this.timeout, …)` that kills the process group if the child is still running, then lets the existing wait/read finish.
- **🔷** `⏳` On `child_exited` / `wait_async` success: `GLib.Source.remove` the timeout id (`0` = none, no nullable).
- **🔷** `⏳` Append to the returned text when the timer fired: `Command timed out after N seconds. Raise timeout in run_command if this was expected to run longer.`
- **🔷** `⏳` Same timer on the VTE spawn path (Phase 3b) and the CLI subprocess path.
- **🔷** `⏳` In `execute()`, before permission: if `this.timeout <= 0` return `ERROR: timeout must be a positive number of seconds`.
- **🔷** `⏳` `to_summary()`: add `Timeout: ` + the seconds when `timeout` is not 60.

### 12. `liboctools/RunCommand/Tool.vala` — describe timeout

**Why:** The model will not raise the cap if the parameter is undocumented.

**Where:** `description` Output / new Timeout bullets; `parameter_description` after `run_as_root`.

**Depends on:** §11.

#### Add — in `description`, after the Output bullets (and replacing the “command is killed” line from 3a)

Timeout:
- Default is 60 seconds. Commands that block (SSH password, missing TTY) are killed at that cap.

## LLM notes

- **🚫** Do not add a secret-helper class or `start_hold()` / `on_hold_tick()` — inline in `ChatPermission`.
- **🚫** Do not make Allow-Always remember root commands (still `one_time_only` for `run_as_root`).
- **🚫** Do not kill the child because the tail is long.
- **🚫** Do not put VTE in `liboctools` if that pulls vte into CLI/Android. GTK widget + a callback/provider is the split.
- **🚫** Do not restore a live VTE from history JSON.
- **🚫** Do not treat a single click as “use saved password”.
- **🚫** Do not use output-idle as the timeout (elapsed time from spawn only).
- **🚫** Do not wait forever when `timeout` is omitted.
