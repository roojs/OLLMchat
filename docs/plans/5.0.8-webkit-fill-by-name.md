## Purpose

- **🔷** Redesign **`fill`** so keys are **form field names**, not ephemeral **press-ref ids**.
- **🔷** Dump markdown must **show those keys** so the model can copy them.
- **🔷** Lock **dump shape** + **tool wire** first (this doc); then implement.
- **🚫** No DOM / page-JS for dump or fill (parent **5.0** veto).

---

## 1 — Current dump (v1)

Editable fields are **pressables** today. Same `(^press:N)` as buttons/links. Current value (if Text exposes it) is appended as `= value`.

```markdown
# Page
- URL: https://www.google.com/…
- Title: Google

## Content
[Search](^press:12){400,120}
[Google Search](^press:15){520,120}

## References
(^press:12): [searchbox] Search
(^press:15): [button] Google Search
```

With typed text already in the box:

```markdown
## Content
[Search](^press:12){400,120} = webkitgtk

## References
(^press:12): [searchbox] Search = webkitgtk
(^press:15): [button] Google Search
```

**How the LLM fills today** — keys are press-ref **ids** (brittle; change every dump):

```json
{
  "action": "press",
  "press": 15,
  "fill": { "12": "webkitgtk at-spi" }
}
```

- **ℹ️** Order: apply `fill`, then press `15`, settle, return new a11y dump.
- **ℹ️** Tool docs say keys are press-ref ids, **not** HTML `name` attributes.

## 2 — Proposed dump (form / fillable)

- **🔷** Keep `(^press:N)` for **activate** (buttons, links, …).
- **🔷** Add a **fill key** on editables so the model does not reuse press ids for typing.
- **💩** Proposal below — **await user lock** on marker form and which string is the key.

### Proposed Content / References (home search box)

```markdown
# Page
- URL: https://www.google.com/…
- Title: Google

## Content
[Search](^fill:Search){400,120}
[Google Search](^press:15){520,120}

## References
(^fill:Search): [searchbox] Search
(^press:15): [button] Google Search
```

With current value:

```markdown
## Content
[Search](^fill:Search){400,120} = webkitgtk

## References
(^fill:Search): [searchbox] Search = webkitgtk
(^press:15): [button] Google Search
```

### Marker rules (proposed — not locked)

| Kind | Content | References |
| ---- | ------- | ---------- |
| Fillable (searchbox / entry / textbox / …) | `[label](^fill:KEY){x,y}` optional `= value` | `(^fill:KEY): [role] label` optional `= value` |
| Pressable only (button / link / …) | `[label](^press:N){x,y}` | `(^press:N): …` (unchanged) |
| Both? | **💩** Prefer **fill-only** marker on editables (pressing a searchbox is rare; submit is a separate button). Or emit **both** `[label](^fill:KEY)(^press:N){x,y}` if we still need press-on-field. |

### What is `KEY`? (lock required)

User lean: **HTML attribute**, not accessible label — ideally **`name=`**.

#### Feasibility (probed 2026-07-25)

WebKit AT-SPI `Accessible.get_attributes()` — we already call this in `A11yParse` for `tag` / `computed-role`.

From WebKit `AccessibilityObjectAtspi::attributes()` (upstream):

| Attribute | Exposed as AT-SPI object attr? | Notes |
| --------- | ------------------------------ | ----- |
| HTML **`id`** | **Yes** — key `"id"` | When non-empty on the element |
| HTML **`tag`** | **Yes** — key `"tag"` | e.g. `input`, `button` |
| **`placeholder`** | **Yes** — key `"placeholder-text"` | |
| HTML **`name`** | **No** | Not in the attribute map at all — form `name=` is **not** published to AT-SPI |
| Accessible **label** | Via `get_name()`, not attrs | What option **A** used |

- **🔷** Prefer attribute keys over accessible label.
- **ℹ️** **`name=` is what you want** for real forms (`email`, `q`, …) — **not available** from a11y without DOM/JS or a **WebKit (or sibling) change** to expose it.
- **ℹ️** **`id=` is available today** via `attrs.get("id")` — same channel as `tag`. No DOM scrape.
- **ℹ️** Google’s search box often has stable **`name="q"`** but an opaque / churning **`id`** — so **`id` alone is a weak Google KEY**.

#### Options (updated)

| Option | Source | Feasible now? |
| ------ | ------ | ------------- |
| **B1** HTML **`name=`** | Need WebKit/sibling to add attr `"name"` (or equivalent) | **⏳** not today on stock WebKitGTK |
| **B2** HTML **`id=`** | `attrs.get("id")` | **✔️** feasible now |
| **B3** Prefer **`name`**, fall back **`id`**, else skip fill marker | Needs B1 first for `name` | Hybrid once `name` exists |
| **A** Accessible label | `get_name()` | Feasible; **user said no** |
| **C** Synthetic fill ids | Our counter | Feasible; brittle like press |
| **D** `role:label` | Derived | Feasible; user lean against label |

#### Paths if we insist on `name=`

1. **💩** Patch / request **WebKit** (and mirror in **webview2-gtk** / **webkitgtk-android**) to add `map.add("name", element->getNameAttribute())` next to `id` in AT-SPI attributes — then OLLMchat reads `attrs.get("name")`. Still **not** DOM scrape from the tool.
2. **🚫** Read `name` via `evaluate_javascript` / DOM — parent **5.0** veto.
3. **💩** Ship **B2 (`id`)** now; add **B1 (`name`)** when engines expose it.

- **⏳** **🔷** User picks: wait for / add engine `name` attr, or use `id` now, or hybrid.

## 3 — How the LLM sends `fill`

Still an **argument** on `action: press` (not a separate action), unless we reopen that.

### Proposed tool call

```json
{
  "action": "press",
  "press": 15,
  "fill": { "Search": "webkitgtk at-spi" }
}
```

- **🔷** `fill` keys copy **`KEY` from `(^fill:KEY)`** in the last a11y output (not press ids).
- **🔷** `press` still the control to **activate** after typing (Search button, Submit, …).
- **🔷** Order unchanged: fill all map entries → press → settle → dump.

### Multi-field example (login-ish)

Dump:

```markdown
## Content
[Email](^fill:Email){80,200}
[Password](^fill:Password){80,240}
[Sign in](^press:40){80,280}

## References
(^fill:Email): [entry] Email
(^fill:Password): [password text] Password
(^press:40): [button] Sign in
```

Call:

```json
{
  "action": "press",
  "press": 40,
  "fill": {
    "Email": "user@example.com",
    "Password": "secret"
  }
}
```

### Wire / docs deltas (after lock)

- **⏳** **🔷** `Tool.parameter_description` — `fill` keys = fill keys from dump, not press-ref ids.
- **⏳** **🔷** `A11y.fill` — resolve via fill-route map (label/name), not `press_routes` only.
- **💩** Accept old numeric press-ref keys as transition alias? (default **no** once dump shows `^fill:`).
