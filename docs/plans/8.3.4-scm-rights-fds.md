# 8.3.4 — `SCM_RIGHTS` fds

> **`docs/plans/1.0-summary.md` is not updated** for this sub-plan until it is done and archived.

**Status:** **PROPOSED** — wire design failed first implementation attempt; see **Why this design failed** below. Code in tree matches the proposed fences; smoke test does not pass yet.

**Parent:** [`8.3-libocrpc-live-handles-and-signals.md`](8.3-libocrpc-live-handles-and-signals.md)

**Pointer:** `docs/guide-to-writing-plans.md` — **Checklist for plans**; proposed Vala follows **`docs/coding-standards.md`**

## Why this design failed (implementation attempt)

First implementation followed the fences below: bin object on **`DataOutputStream`**
as today, in-band trailer **`0xFC`** on the stream, flush, then
**`Buffer.send()`** (`sendmsg` with a one-byte iov + **`SCM_RIGHTS`**). Receive:
**`bin_read`**, peek **`0xFC`** on the input stream, consume it, then
**`Buffer.receive()`** (`recvmsg`).

**It does not work reliably on a live Unix stream socket.**

GIO **`DataOutputStream`** over a socket sends bin bytes with ordinary
**`send`/`sendto`** syscalls. **`Buffer.send()`** adds a separate
**`sendmsg`** for the ancillary fd (plus its own one-byte iov). On the receive
side, **`DataInputStream`** reads with **`read`/`recvfrom`**, which can
**read-ahead** (large buffered reads).

**Observed behaviour** (reproduced with strace on a **`socketpair`** smoke test
and a minimal C **`write` + `sendmsg`** program):

1. Server sends ~193 bytes of bin data via **`sendto`**, then **`sendmsg`**
   (1 data byte + fd).
2. Client **`recvfrom`** reads 194 bytes — **one byte more than the bin
   payload** — without using **`recvmsg`**.
3. That extra byte is the **`sendmsg`** data byte (and/or the in-band **`0xFC`**
   trailer). **`SCM_RIGHTS` fds are only delivered to `recvmsg`**, not to
   plain **`read`**. The fd is **lost**.
4. A subsequent **`recvmsg`** in **`Buffer.receive()`** gets **`EAGAIN`**
   (nothing left to receive as a control message); **`notif.buffer.fd`** stays
   **`-1`**.

So mixing **stream writes** and a follow-up **`sendmsg`** on the **same** socket
fd, while the peer parses with **`DataInputStream`**, cannot guarantee the fd
survives. Peeking/consuming **`0xFC`** on the byte stream does not fix it — the
damage happens when **`read`** slurps the **`sendmsg`** byte before **`recvmsg`**
runs.

**Not a fix (attempted without approval):** encoding the whole object + trailer
in **one** **`sendmsg`** and **`recvmsg`**-first on parse — that changes the wire
shape and was reverted.

**Open:** need a revised design before this plan can be marked done. **Draft:** **`Live.BufferStream`**
(§ **Revised design (draft): BufferStream** below).

**Note:** **`GLib.DataInputStream`** has no **`peek_byte()`**; the v1 tree uses
**`BufferedInputStream.peek`** for the trailer check. That does not fix the
**`read`** vs **`recvmsg`** fd loss above.

## Revised design (draft): `Live.BufferStream`

**Goal.** Keep the **main RPC socket** as plain bin stream I/O only. Move all
**`SCM_RIGHTS`** traffic to a **second Unix stream** owned by
**`Live.BufferStream`**. No in-band **`0xFC`** trailer on the bin socket. No
threads — same GLib main loop as today.

### Who passes what

| Layer | Passes | Does **not** pass |
| ----- | ------ | ----------------- |
| **App / gnome-shell-rpc** | **`Live.Buffer(fd)`** to **`Connection.write(notif, buffer)`** | **`BufferStream`**, raw **`GLib.Socket`** |
| **`Connection` / `Client`** | Holds one **`BufferStream?`** for the connection lifetime | Socket to callers |
| **`Bin.Stream`** | Nothing SCM-related (no **`socket`** field for fds) | **`Buffer`** on **`write()`** — **`Connection`** orchestrates |
| **`Live.Buffer`** | One fd per send/recv | Channel setup |

**Yes — internally you pass `BufferStream`, not the main RPC socket.** The main
**`GLib.Socket`** stays on **`Bin.Stream`** I/O only (or only on
**`SocketConnection`**). **`Buffer.send()`** / **`receive()`** take
**`BufferStream`**, which wraps the **fd channel** socket.

Callers keep the same shape:

```vala
connection.write(new Notification() { … }, new Live.Buffer(dmabuf_fd));
// client:
client.notification.connect((notif) => { var fd = notif.buffer.fd; });
```

### Lifecycle

- Open the **fd channel** when the RPC connection comes up (same time as main
  socket), **only** when fd passing is enabled (gnome-shell-rpc / **`live_handles`**).
- **`Connection`** (server) and **`Client`** (client) each hold
  **`public Live.BufferStream? buffer_stream { get; … }`** — **`null`** when
  disabled or on Windows/Android stubs.
- Teardown: close fd channel when main connection stops.

**Wire for fd channel (TBD):** second path (e.g. **`socket_path + ".fd"`**),
extra leg from accept, or hello metadata — pick one when implementing; not on the
bin wire.

### Ordering (no correlation id in v1)

1. Server **`buffer_stream.send(buffer)`** — **`sendmsg`** + fd on **fd channel only**.
2. Server **`bin.write(notif)`** on **main** socket — ordinary notification, no fd.

Client (single thread, main loop):

- **Option A (sync):** when dispatching a **`Notification`**, if **`buffer_stream`**
  is active, **`notif.buffer = buffer_stream.take_pending()`** (fd already
  received if server sent fd-first).
- **Option B (watch):** **`BufferStream`** registers an **`IOChannel`/`Socket` watch**
  on the fd channel; each **`recvmsg`** pushes a **`Live.Buffer`** onto an internal
  FIFO; **`take_pending()`** pops when the main watch parses the notification.

Both are **one thread** — no blocking worker, no condition variables. Option B
matches the existing client read-watch pattern.

### Mockup — `Live.BufferStream.vala` (new)

```vala
namespace OLLMrpc.Live
{
	/**
	 * Per-connection fd channel — all ''SCM_RIGHTS'' ''sendmsg''/''recvmsg''
	 * on a socket separate from the main bin RPC stream.
	 */
	public class BufferStream : GLib.Object
	{
		public GLib.Socket? socket { get; private set; default = null; }

		internal Gee.ArrayQueue<Buffer> pending {
			get;
			private set;
			default = new Gee.ArrayQueue<Buffer>();
		}

		/** Server: wrap accepted fd leg. Client: wrap connected fd socket. */
		public BufferStream(GLib.Socket socket)
		{
			this.socket = socket;
		}

		/** ''sendmsg'' one fd (server). Called before notification on main socket. */
		public void send(Buffer buffer) throws GLib.Error
		{
			buffer.send(this.socket);
		}

		/** Pop next received fd (client). FIFO — matches fd-first send order. */
		public Buffer? take_pending()
		{
			if (this.pending.size == 0) {
				return null;
			}
			return this.pending.poll();
		}

		/** One ''recvmsg''; push ''Buffer'' with stolen fd. Watch or sync call. */
		internal void receive_one() throws GLib.Error
		{
			var buffer = new Buffer();
			buffer.receive(this.socket);
			this.pending.offer(buffer);
		}

		public void start_watch()
		{
			// IO watch on this.socket → receive_one() when IN (client path)
		}

		public void close()
		{
			// remove watch, close socket
		}
	}
}
```

## What this plan is for (read this first)

**Background.** gnome-shell-rpc needs to pass a **dmabuf fd** with a **`Notification`**. The fd cannot go in bin bytes — Linux moves it with **`SCM_RIGHTS`**.

**Design (v1 — failed).** In-band **`0xFC`** trailer on the main bin socket + **`Buffer.send()`** on the same fd — see **Why this design failed**. Fences below (§1–§12) describe v1; **do not implement** until revised for **`BufferStream`**.

**Design (v2 — draft).** Separate **fd channel** via **`Live.BufferStream`**; main socket stays bin-only; **`Connection.write(notif, buffer)`** sends fd then notification. See **Revised design (draft): BufferStream** above.

**Caller shape (unchanged):**

```vala
connection.write(new Notification() {
    method = "Window.thumbnail",
    object_type = "Window",
    id = (int) handle
}, new Live.Buffer(dmabuf_fd));

client.notification.connect((notif) => {
    var fd = notif.buffer.fd;
});
```

**Fd-less traffic.** Pass **`null`** for buffer — no trailer, no SCM. ollmfilesd unchanged.

**Windows / Android.** No Unix sockets — same **`Live/namespace.vala`** stub path as Windows. **`#if G_OS_WIN32 || ANDROID`**. Live RPC never used there. **`namespace.vala`** is always in **`live_src`** (harmless on Unix — **`#if`** block empty); Unix adds real **`Live/*.vala`**.

#### Add — create `libocrpc/Live/Buffer.vala`

```vala
/*
 * Copyright (C) 2026 Alan Knowles <alan@roojs.com>
 *
 * This library is free software; you can redistribute it and/or
 * modify it under the terms of the GNU Lesser General Public
 * License as published by the Free Software Foundation; either
 * version 3 of the License, or (at your option) any later version.
 *
 * You should have received a copy of the GNU Lesser General Public License
 * along with this library; if not, write to the Free Software Foundation,
 * Inc., 51 Franklin Street, Fifth Floor, Boston, MA  02110-1301  USA
 */

namespace OLLMrpc.Live
{
	/**
	 * One fd passed over ''SCM_RIGHTS'' on a Unix stream socket.
	 *
	 * Caller sets {@link fd} and passes this to
	 * {@link OLLMrpc.Transport.Connection.write}. {@link OLLMrpc.Bin.Stream}
	 * calls {@link send} / {@link receive} after the trailer byte.
	 */
	public class Buffer : GLib.Object
	{
		public int fd { get; set; default = -1; }

		public Buffer(int fd = -1)
		{
			this.fd = fd;
		}

		public void send(GLib.Socket socket) throws GLib.Error
		{
			uint8 tag = 0;
			GLib.OutputVector[] vectors = {
				GLib.OutputVector() {
					buffer = &tag,
					size = 1
				}
			};
			var fd_list = new GLib.UnixFDList();
			fd_list.append(this.fd);
			GLib.SocketControlMessage[] messages = {
				new GLib.UnixFDMessage.with_fd_list(fd_list)
			};
			socket.send_message(null, vectors, messages, 0, null);
		}

		public void receive(GLib.Socket socket) throws GLib.Error
		{
			uint8 tag = 0;
			GLib.InputVector[] vectors = {
				GLib.InputVector() {
					buffer = &tag,
					size = 1
				}
			};
			GLib.SocketControlMessage[]? messages = null;
			int flags = 0;
			ssize_t n = socket.receive_message(
				null,
				vectors,
				out messages,
				ref flags,
				null
			);
			if (n <= 0) {
				throw new GLib.IOError(
					GLib.IOErrorEnum.FAILED,
					"Buffer receive failed"
				);
			}
			this.fd = -1;
			if (messages == null) {
				return;
			}
			foreach (var cm in messages) {
				var fd_msg = cm as GLib.UnixFDMessage;
				if (fd_msg == null) {
					continue;
				}
				var stolen = fd_msg.steal_fds();
				if (stolen.length > 0) {
					this.fd = stolen[0];
					return;
				}
			}
		}
	}
}
```
