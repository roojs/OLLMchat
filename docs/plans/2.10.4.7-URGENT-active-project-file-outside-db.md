## Purpose

- 🔷 Drop **active project** and **active file** as **daemon / SQLite** concerns.
- 🔷 Frontend owns which project / file / agent a window shows.
- 🔷 Persist that in **Config2** via a new **`Window`** settings class (not on `AgentConfig`).
- 🔷 Design the map for **multi-window** now (keyed window ids → per-window config), even though only **one** window exists today.
- 🔷 Immediate safety: **stop sending `File.activate`** (and harden daemon / client timeouts — Phase 0 below).

---

## Why now

- ℹ️ Daemon log: `File.activate` → CRITICAL `no signal call_activate` → **no reply** → RPC queue stall → unexpected response id abort.
- 🔷 Product already wanted activation **off the backend** (this file’s earlier FUTURE text).
- 🔷 Multi-window will need **per-window** project / file / agent — one global daemon `active_*` cannot work.

---

## Target model

### Runtime (unchanged shape)

- 🔷 Each GTK window keeps a `ProjectManager` with in-memory `active_project` / `active_file` for tools and UI.
- 🔷 Daemon owns files, folders, scan, index, disk I/O — **not** “what the user is looking at”.

### Persistence (Config2)

- 🔷 New serializable class **`OLLMchat.Settings.Window`** (name approved by user).
- 🔷 `Config2` holds a map of window id → `Window`.
- 🔷 Today: **one** entry (single main window).
- 🔷 Later: hashed / stable window ids → one config blob each.

| Field on `Window` | Meaning |
| ----------------- | ------- |
| 🔷 `project` (path string) | Open project path for this window |
| 🔷 `file` (path string) | Open file path (empty = none) |
| 🔷 `agent` (factory id string) | Agent in use (e.g. `agent-pi`, `just-ask`) |

💩 Exact JSON property names (`project` / `file` / `agent` vs `project_path` / `file_path` / `agent_name`) — prefer short names matching user wording unless review wants `_path` suffix for clarity.

💩 Window map key scheme for multi-window — options:
- 💩 Stable id assigned when the GTK window is created (UUID), stored for the life of that window instance
- 💩 Fixed key `"main"` while only one window exists; real hashes when multi-window lands
- 🚫 Do not use ephemeral Gtk widget pointers as persisted keys

### JSON sketch

```json
"windows": {
  "main": {
    "project": "/home/alan/gitlive/OLLMchat",
    "file": "/home/alan/gitlive/OLLMchat/docs/plans/6.2-speech-to-text.md",
    "agent": "agent-pi"
  }
}
```

## Phases

### Phase 0 — Stop the crash / stop dead RPC ⏳ 🔷

**Goal:** No more `File.activate` on the wire; unknown methods must reply; timeouts must not expire while queued.

ℹ️ Crash evidence: [`docs/bugs/2026-08-06-rpc-unexpected-response-id-aborts-app.md`](../bugs/2026-08-06-rpc-unexpected-response-id-aborts-app.md).

🚫 Phase 0 does **not** invent Config2 `Window` persistence — that is Phase 1+.

#### 0.1 `libocfiles/ProjectManager.vala` — `activate_file`: drop RPC

**Why:** Daemon no longer implements `File.activate`; local state + signal are enough.

**Where:** `public void activate_file`.

##### Remove

```vala
			this.rpc.call.begin(new OLLMrpc.Request() {
				method = "File.activate",
				param = new OLLMfilesd.ProjectParams() {
					path = file != null ? file.path : ""
				}
			}, (obj, res) => {
				this.rpc.call.end(res);
			});
```

(Keep the local `active_file` / `is_active` / `active_file_changed` work above.)

Tighten the method docblock: remove “RPC is fire-and-forget” — activate is client-local only.

#### 0.2 `libocrpc/Transport/Connection.vala` — `on_input_ready`: reply on failed dispatch

**Why:** Any unknown/missing `call_*` must not leave the client waiting until timeout.

**Where:** after `request.dispatch();` in the read loop.

##### Remove

```vala
				request.connection = this;
				request.dispatch();
```

##### Replace with

```vala
				request.connection = this;
				if (!request.dispatch()) {
					this.reply_error(
						request,
						(int) OLLMrpc.RpcErrorCode.METHOD_NOT_FOUND
					);
				}
```

#### 0.3 `libocrpc/Client.vala` — timeout from **send**, not enqueue

**Why:** Queued calls must not expire while blocked behind a hung in-flight head.

**Where:** `PendingWrite` / `wait_response` / `send_head` / `complete_pending`.

##### Part 1 — `PendingWrite`: hold timeout source id

##### Add — On `PendingWrite` (near existing fields):

```vala
			public uint timeout_id { get; set; default = 0; }
```

##### Part 2 — `wait_response`: do not arm timeout here

##### Remove — The whole `if (this.call_timeout_seconds > 0) { Timeout.add_seconds(...); }` block and the `finally { Source.remove(timeout_id); }` wrapper; keep only:

```vala
			return yield entry.promise.future.wait_async();
```

##### Part 3 — `send_head` (socket path): arm timeout when `head.sent = true`

##### Add — Immediately after `head.sent = true;` on the successful bin write/flush path:

```vala
				if (this.call_timeout_seconds > 0 && head.timeout_id == 0) {
					var timed = head;
					head.timeout_id = GLib.Timeout.add_seconds(
						this.call_timeout_seconds,
						() => {
							GLib.warning(
								"call timed out %s id=%d after %u s",
								timed.request.method,
								timed.request.id,
								this.call_timeout_seconds
							);
							timed.timeout_id = 0;
							this.complete_pending(
								timed.request.id,
								null,
								new GLib.IOError.TIMED_OUT("call timed out")
							);
							return false;
						}
					);
				}
```

##### Part 4 — `complete_pending`: clear timeout source

##### Add — After removing `entry` from `pending`, before `set_value`:

```vala
				if (entry.timeout_id != 0) {
					GLib.Source.remove(entry.timeout_id);
					entry.timeout_id = 0;
				}
```

### Phase 1 — `Settings.Window` + `Config2.windows` ⏳ 🔷

**Goal:** Type + map exist and round-trip in `config.2.json`.

#### Add — New file `libollmchat/Settings/Window.vala` (full class)

```vala
namespace OLLMchat.Settings
{
	/**
	 * Per-window UI chrome persisted in {@link Config2}.
	 *
	 * Keys in {@link Config2.windows} are stable window ids (today: ''main'').
	 * Runtime {@link OLLMfiles.ProjectManager} still holds live
	 * ''active_project'' / ''active_file'' objects; this type stores paths
	 * and agent id for restore.
	 */
	public class Window : Object, Json.Serializable
	{
		[Description(nick = "Project", blurb = "Absolute project path")]
		public string project { get; set; default = ""; }

		[Description(nick = "File", blurb = "Absolute open file path")]
		public string file { get; set; default = ""; }

		[Description(nick = "Agent", blurb = "Agent factory id")]
		public string agent { get; set; default = ""; }
	}
}
```

#### Add — On `Config2`: `windows` map (same pattern as `agents`)

```vala
		/**
		 * Map of window id → {@link Window} (UI chrome per window).
		 */
		public Gee.Map<string, Window> windows {
			get; set; default = new Gee.HashMap<string, Window>();
		}
```

(Wire serialize/deserialize like `agents` — implementer follows existing Config2 map pattern; meson + valadoc lists.)

💩 Default seed: ensure `"main"` exists on load if map empty.

### Phase 2 — Single-window restore / save ⏳ 🔷

**Goal:** Main `ollmapp/Window` reads/writes `config.windows["main"]` (or chosen key).

- 🔷 On project change / file open / agent change: update the `Window` row and save Config2 (debounce 💩).
- 🔷 On startup: after projects load, apply `project` / `file` / `agent` from that row into local PM + session (replace reliance on SQLite `is_active` for restore).
- ℹ️ Session JSON may still carry `project_path` for chat history — do not fight that in Phase 2; Config2 is the **window chrome** source of truth for “what was open”.

### Phase 3 — Daemon slim (activation) ⏳ 🔷

**Goal:** Daemon no longer treats activation as UI state.

- 🔷 `ProjectManager.activate_project` RPC: keep only if needed as **scan / open path** — rename or document as non-UI (e.g. ensure scanned). Prefer path-driven scan RPC over “activate”.
- 🔷 Stop persisting / reading SQLite `is_active` for UI restore.
- 🔷 Remove any remaining `File.activate` expectations from tests / docs.

### Phase 4 — Multi-window keys ⏳ 🔷 (design now, implement when second window exists)

- 🔷 When a second GTK window is created: allocate a stable id, insert `Config2.windows[id]`, bind that window’s PM to that row.
- 🔷 Closing a window: 💩 keep last chrome in config vs delete key — decide at implementation.
- 🚫 Do not add `window_id` on daemon activate RPCs — multi-window is solved by **no daemon activation**.
