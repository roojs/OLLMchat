## Purpose

- 🔷 Drop **active project** and **active file** as **daemon / SQLite** concerns.
- 🔷 Frontend owns which project / file / agent a window shows.
- 🔷 Persist that in **Config2** via a new **`Window`** settings class (not on `AgentConfig`).
- 🔷 Design the map for **multi-window** now (keyed window ids → per-window config), even though only **one** window exists today.
- 🔷 Immediate safety: **stop sending `File.activate`**; daemon must **`reply_error` on failed dispatch** (Phase 0).

---

## Why now

- ℹ️ Daemon log: `File.activate` → CRITICAL `no signal call_activate` → **no reply** → RPC queue stall → unexpected response id abort.
- 🔷 Product already wanted activation **off the backend** (this file’s earlier FUTURE text).
- 🔷 Multi-window will need **per-window** project / file / agent — one global daemon `active_*` cannot work.

---

## Target model

### Runtime (unchanged shape)

- 🔷 Each GTK window keeps a `ProjectManager` with in-memory `active_project` / `active_file` for tools and UI.
- 🔷 Daemon owns files, folders, scan, index, disk I/O — **not** “what the user is looking at”.

### Persistence (Config2)

- 🔷 New serializable class **`OLLMchat.Settings.Window`** (name approved by user).
- 🔷 `Config2` holds a map of window id → `Window`.
- 🔷 Map keys are a **UUID string** per window (`GLib.Uuid.string_random()` — same pattern as CLI tool call ids).
- 🔷 Today: **one** entry (single window still gets a UUID).
- 🔷 Later: one key per open window.

| Field on `Window` | Meaning |
| ----------------- | ------- |
| 🔷 `project` (path string) | Open project path for this window |
| 🔷 `file` (path string) | Open file path (empty = none) |
| 🔷 `agent` (factory id string) | Agent in use (e.g. `agent-pi`, `just-ask`) |

💩 Exact JSON property names (`project` / `file` / `agent` vs `project_path` / `file_path` / `agent_name`) — prefer short names matching user wording unless review wants `_path` suffix for clarity.

🔷 Window map key: assign `GLib.Uuid.string_random()` when the GTK window is first created; keep that string on the window and in `Config2.windows` for the life of that chrome row (survives restarts for that row).

🚫 Do not use `Gtk.ApplicationWindow.get_id()` as the persisted key (process-local only).  
🚫 Do not use ephemeral Gtk widget pointers as persisted keys.  
🚫 Do not use a fixed label key like `"main"`.

### JSON sketch

```json
"windows": {
  "a3f1c9e2-b8d0-4f6a-9c1e-2d4b6a8c0e1f": {
    "project": "/home/alan/gitlive/OLLMchat",
    "file": "/home/alan/gitlive/OLLMchat/docs/plans/6.2-speech-to-text.md",
    "agent": "agent-pi"
  }
}
```

## Phases

### Phase 0 — Stop the crash / stop dead RPC ✔️ 🔷

**Goal:** No more `File.activate` on the wire; unknown/missing `call_*` must reply with an error (never hang silently).

ℹ️ Crash evidence: [`docs/bugs/2026-08-06-rpc-unexpected-response-id-aborts-app.md`](../bugs/2026-08-06-rpc-unexpected-response-id-aborts-app.md).

🚫 Phase 0 does **not** invent Config2 `Window` persistence — that is Phase 1+.  
🚫 Do **not** “fix” the abort by moving call timeouts, softening `GLib.error` on unexpected response ids, or other client timeout/queue cosmetics — those paper over missing replies. Cause fixes only: **0.1** + **0.2**.

#### 0.1 `libocfiles/ProjectManager.vala` — `activate_file`: drop RPC ✔️

**Why:** Daemon no longer implements `File.activate`; local state + signal are enough.

**Where:** `public void activate_file`.

##### Remove

```vala
			this.rpc.call.begin(new OLLMrpc.Request() {
				method = "File.activate",
				param = new OLLMfilesd.ProjectParams() {
					path = file != null ? file.path : ""
				}
			}, (obj, res) => {
				this.rpc.call.end(res);
			});
```

(Keep the local `active_file` / `is_active` / `active_file_changed` work above.)

Tighten the method docblock: remove “RPC is fire-and-forget” — activate is client-local only.

#### 0.2 `libocrpc/Transport/Connection.vala` — `on_input_ready`: reply on failed dispatch ✔️

**Why:** Any unknown/missing `call_*` must not leave the client waiting until timeout.

**Where:** after `request.dispatch();` in the read loop.

##### Remove

```vala
				request.connection = this;
				request.dispatch();
```

##### Replace with

```vala
				request.connection = this;
				if (!request.dispatch()) {
					this.reply_error(
						request,
						(int) OLLMrpc.RpcErrorCode.METHOD_NOT_FOUND
					);
				}
```

#### 2.3 `libocfiles/ProjectManager.vala` — path-based `restore_active_state`

**Why:** Docblock already says paths come from window config and must not use DB `is_active`; implementation still calls `get_active_project()`.

##### Remove — Current method body (signature through closing `}`)

```vala
		public async void restore_active_state(string? file_path = null)
		{
			var project = this.projects.get_active_project();
			if (project == null) {
				foreach (var other_project in this.projects.project_map.values) {
					if (other_project.is_project && other_project.is_active) {
						other_project.is_active = false;
					}
				}
				return;

			}

			}
		}
```

##### Replace with

```vala
		/**
		 * Restore active project and file from Config2 window chrome paths.
		 *
		 * Does not read DB ''is_active'' flags. Empty ''project_path'' is a
		 * no-op. Empty ''file_path'' activates the project only.
		 *
		 * @param project_path Absolute project path from {@link OLLMchat.Settings.Window.project}
		 * @param file_path Absolute file path from {@link OLLMchat.Settings.Window.file}, or empty
		 */
		public async void restore_active_state(string project_path, string file_path = "")
		{
			if (project_path == "") {
				return;
			}
			if (!this.projects.path_map.has_key(project_path)) {
				GLib.warning("restore: project path not in list: %s", project_path);
				return;
			}
			var project = this.projects.path_map.get(project_path);
			GLib.debug("restoring window chrome project path=%s", project.path);
			this.activate_project(project);
			if (file_path == "") {
				return;
			}
			var file = yield project.fetch_file(file_path);
			if (file != null) {
				this.activate_file(file);
			}
		}
```
