## Purpose

- **🔷** `⏳` Let the **client** register a handler and get a **callback id**.
- **🔷** `⏳` On typelib invoke, when GIR wants a `CALLBACK`, the wire carries that **id** (a number), not a C function pointer.
- **🔷** `⏳` Server installs a **fixed trampoline** as the C handler. Trampoline `user_data` holds the id (and connection).
- **🔷** `⏳` When mutter calls the trampoline, server **notifies the client** with the id + packed args (same direction as signal subscribe).
- **🔷** `⏳` Client looks up the id and runs the real Vala/JS handler.
- **🔷** `⏳` Same `live_handles` flag. Flag off → no callback path (ollmfilesd unchanged).
- **ℹ️** This is **not** GObject signal subscribe. Registration is an **argument** to a Meta API, not `g_signal_connect`.
- **🚫** Do not invent Meta APIs. Do not noop shell-used keybinding / idle APIs in the consumer.

---

## Why (one picture)

Signals today (`8.3.2`):

```
client: Subscribe.signal(lease, "closed")
server: connect_swapped → Subscription.emit → Notification
```

Callbacks (this plan):

```
client: register callable → callback_id
client: add_keybinding(..., callback_id, ...)   // wire: uint where GIR has CALLBACK
server: Gi.convert(CALLBACK) → trampoline + user_data = { connection, callback_id }
mutter: key press → trampoline(display, window, event, binding, user_data)
server: Notification { method=RPC-Live-Callback.invoke, id=callback_id, args=... }
client: run registered handler
```

**DestroyNotify:** when mutter frees the binding, trampoline’s destroy path drops the server-side row for that id (and may notify client to drop).

## Same as signals / different

| | Signals (`8.3.2`) | Callbacks (this) |
| --- | --- | --- |
| Opt-in | `live_handles` | same |
| Id | lease id of GObject | **callback id** (new table) |
| Server C glue | `Subscription.emit` | trampoline matching GIR callback signature |
| Client ← server | `Notification` | `Notification` (phase 1: fire-and-forget) |
| Register how | `RPC-Live-Subscribe.signal` | register callable, then pass id into typelib call |
| Sync return | no | **phase 2** only (`foreach` needs `bool`) |

## Suggested design (for sign-off)

### 1. Callback id

- **🔷** `⏳` Per-connection map: `callback_id →` row (at least connection; optional GIR callback name for debug).
- **💩** `⏳` Client allocates id via `RPC-Live-Callback.register` (reply with id), **or** client picks id and server learns it on first typelib arg — pick one in implementation; prefer explicit register like subscribe.
- **🔷** `⏳` Connection drop clears all callback rows for that peer (same as leases / signal_subs).

### 2. Wire on typelib IN

- **🔷** `⏳` Where GIR arg is `CALLBACK`, request arg is **`UINT64` / `UINT32` callback id** (same “it’s just a number” idea as object leases).
- **🔷** `⏳` `user_data` / `DestroyNotify` that travel with the callback in GIR: server-owned. Client does **not** send a real `gpointer` or C destroy. Generator packs only the callback id; server supplies trampoline `user_data` + destroy that frees the row.
- **ℹ️** GJS hides `user_data` / destroy; Vala stubs currently expose them — generator may omit or ignore those slots once wired.

### 3. Server trampoline

- **🔷** `⏳` One trampoline family per **callback signature** we support (start with idle watch; then key handler).
- **🔷** `⏳` Pattern mirrors `Subscription.emit`: static C-callable method, `user_data` is a small `GLib.Object` holding `connection` + `callback_id`.
- **🔷** `⏳` On invoke: `connection.write(new Notification() { ... })` — **do not block** the compositor waiting for the client (phase 1).
- **💩** `⏳` Wire method name e.g. `RPC-Live-Callback.invoke`; `Notification.id` = callback id; `message` / args = packed GI arguments (display, window, …). Exact packing bikeshed at implement time — reuse lease export for GObjects.

### 4. Client side

- **🔷** `⏳` Client keeps `callback_id →` local delegate / closure.
- **🔷** `⏳` On `Notification` invoke: look up id, call delegate with unpacked args.
- **🔷** `⏳` Stub for `add_idle_watch`: register local func → id → `call_values(..., id)` instead of `GLib.error`.

### 5. Phase 2 (foreach) — explicit later

- **🔷** `⏳` Needs **request/reply** (or a dedicated sync invoke) so trampoline can return `bool` to mutter.
- **🚫** Do not use blocking sync on the compositor thread without a design that keeps mutter responsive.
- **ℹ️** May stay a gap longer than B1/B2; consumer plan already notes list-walk alternatives are inventing Meta.

## Suggested order

1. **🔷** `⏳` Agree model (this doc) — id + trampoline + Notification.
2. **🔷** `⏳` Idle-watch path only (simplest args) + rpc test with a dummy GObject API or smoke typelib.
3. **🔷** `⏳` `Gi.convert` CALLBACK + DestroyNotify ownership.
4. **🔷** `⏳` Key-handler trampoline once `Clutter.Event` packing exists (or notify with null/partial event first — **ask** before shipping partial).
5. **🔷** `⏳` gnome-shell-rpc generator wires B2 then B1 stubs.
6. **🔷** `⏳` Phase 2 foreach — separate sign-off.
