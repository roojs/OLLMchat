## Purpose

- **🔷** `⏳` `Window.created` can carry a live GObject (handle on the wire), not only a string `message`.
- **🔷** `⏳` `Notification` grows a `GLib.Object` payload. Not `Bin.Serializable`.
- **🔷** `⏳` Keep existing string/progress fields working for ollmfilesd banners.
- **🔷** `⏳` `bin_write_prop` **skips** the payload when `live_handles` is off (or payload is unset). Default decode of old notifications stays valid. **No protocol version bump.**
- **🔷** `⏳` When the flag is on, write the payload as a **live handle** ([`8.3.1`](8.3.1-live-handles-and-remote-refcount.md)), not a nested property dump.
- **ℹ️** `docs/bin-rpc-protocol.md` — document the optional property and the skip rule. Leave the spec at v3.0.
- **ℹ️** gnome-shell-rpc still chooses **which** aliases to `Bin.register` (`Display`, `Window`, `Workspace`). That curated surface is not this plan.

---

## LLM notes

- Domain types stay out of `libocrpc`. Tests use dummy `GLib.Object`s.
- Do not bump bin protocol version or `Daemon.protocol`. Gate with the flag and skip on write.
- Do not add a `Bin.Mode` bit for this. `Mode` is JSON/auto decode.
- Subscribe / unsubscribe is [`8.3.2`](8.3.2-subscribe-unsubscribe.md), not this plan.
