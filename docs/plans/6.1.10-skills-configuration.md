## Purpose

- 🔷 `⏳` Ship a **skills configuration** UI for Agent Pi.
- 🔷 That config chooses the **recommended / initial offer** — which skills appear in the system-prompt catalog (`{skills_md}` / `SkillSet.to_prompt`) when a turn starts.
- 🔷 Available skills can be a **larger** set than the initial offer (not a dump of everything into the prompt).
- 🔷 By default skills **run from the resource system** (gresource / packaged `resources/pi-skills/`) — **no** need to copy them onto the filesystem for normal use.
- 🔷 Config can **export** a skill resource → user filesystem; user-edited copy **overrides** the resource skill.
- ℹ️ Loader / scan roots partly exist (`SkillSet.scan`); extend for resource root + export/offer UI.

---

## Two layers (catalog)

- 🔷 **Available** — skills visible to the config UI (resource pack + any user/project filesystem skills).
- 🔷 **Initially offered** — subset whose name + description + path go into `<available_skills>` for Agent Pi.
- 🔷 Configuration dialog edits **initially offered**.
- ℹ️ Model still `read`s full `SKILL.md` only when it chooses a catalog entry (progressive disclosure unchanged).

---

## Resource vs filesystem (source + export)

- 🔷 **Default source:** packaged / gresource (`resources/pi-skills/` from [done/03](done/6.1.3-DONE-base-skills.md)). Catalog `location` can be a resource path the `read` tool can open — **no** silent copy-on-first-use of the whole pack.
- 🔷 **User source:** filesystem under existing scan roots (especially `~/.local/share/ollmchat/pi-skills/`). Same name as a resource skill → **user wins** (override), matching today’s later-scan-wins / by-name replace idea.
- 🔷 Config **A — Export:** convert/copy one skill from resource → filesystem so the user can edit it.
- 🔷 Config **B — Flag:** UI shows clearly when that skill is **exported** (user copy present / overriding resource).
- 🔷 🚫 Config does **not** delete the exported filesystem skill.
  - Removing the override is out of band (e.g. ask the LLM / delete the folder yourself).
- 💩 Exact export target dir for global vs project — prefer global user data dir unless we add a chooser later.
- 💩 Whether “exported” is detected by “file exists under user root with same name” vs a persisted flag — detect-from-disk is enough if export always lands in the known user root.
- ℹ️ Ties acquisition in [done/03](done/6.1.3-DONE-base-skills.md): ship in resources; export-on-demand via this dialog — not blanket A→C for every skill.

## Do skills declare other skills they need?

- ℹ️ **Agent Skills frontmatter has no skill→skill dependency field.**
  - Required: `name`, `description`.
  - Optional: `license`, `compatibility` (environment / packages / network — **not** other skills), `metadata`, `allowed-tools`.
- ℹ️ Soft skills often **name companions in the markdown body** (prose), e.g. superskills `writing-plans` says hand off / **REQUIRED SUB-SKILL** → `executing-plans`.
- ℹ️ That is advice for the **model after it has read the skill**, not a host contract.
- 🔷 Host must **not** assume machine-readable “requires skill X” today.
- 🔷 When choosing the **default initial offer**, include companions that the recommended skills routinely hand off to (e.g. if `writing-plans` is offered, also offer `executing-plans`).
- 🔷 `⏳` **Later:** review how a skill **writes** another skill (body prose / naming) before any UI or parser for companions — see then; not v1.
- 🚫 Do not invent a private frontmatter `depends:` unless we deliberately extend the format later.
- 🚫 No “mentioned companions” settings hint until that later look.

## Configuration dialog

- 🔷 `⏳` Settings UI (Agent Pi / skills page) listing **available** skills (resource + user/project).
- 🔷 Each row:
  - enable for **initial offer** (toggle / check)
  - **exported** flag when a user filesystem copy overrides the resource skill
  - **Export** action when still resource-only (copy to user skill dir)
- 🔷 🚫 No **Delete** (or uninstall) of the exported copy from this UI.
- 🔷 Persist offer selection (config / prefs — exact store **💩** until lock; likely `Config2` beside other agent settings).
- 🔷 Fresh install defaults = a **recommended initial set** (not “everything vendored”).
- ℹ️ Precedent for enable lists: `SettingsDialog/ToolsPage` (tools on/off), not a copy of Runner skill management.
- 💩 Exact chrome: new Settings tab vs group under an Agent page — lock when implementing.
- 💩 Project-local overrides of the offer set — out of v1 unless we already want them; global offer + project scan for *available* is enough to start.

### Behaviour wire-up

- 🔷 `✔️` `SkillSet.scan` includes the **resource** base pack (read-only) plus existing filesystem roots; same-name user/project replaces resource — landed with [done/03](done/6.1.3-DONE-base-skills.md).
- 🔷 `⏳` After scan, filter so only **offered** skills appear in `{skills_md}`.
- 🔷 Available but not offered: still listed in settings; model does not see them until offered.
- 🔷 `⏳` Export: materialize skill tree to user data dir; refresh scan so catalog `location` points at the filesystem copy.
- 💩 Whether the model may `read` a known path outside the catalog — leave as today (soft); catalog is the supported menu.
- 🚫 Do not require npm / `pi install` for this dialog.
- 🚫 Do not copy the whole pack to disk on first run.

## Recommended initial set (defaults)

🔷 Defaults are the **product recommendation** for what Agent Pi advertises on a new install.  
ℹ️ Vendored / gap-fill content still owned by [done/03](done/6.1.3-DONE-base-skills.md) (+ [11](6.1.11-extended-base-skills.md) later); this list is **which start offered**.

Proposed default offer (lock in review):

- 🔷 `⏳` Core workflow defaults: `writing-plans`, `executing-plans`, `brainstorming` (skills exist in 03 pack; offer filter not wired)
- 🔷 `⏳` Code / local defaults: `research-codebase`, `debug-review` (skills exist in 03 pack; offer filter not wired)
- 💩 Architecture / prompt: `senior-solution-architect`, `prompt-engineer` — include in default offer or leave available-only?
- 💩 Web: `deep-research`, `webpage-reader` — available by default, **offered** only if we want browser-heavy agents out of the box
- 💩 Orchestrator: `agent-skill-orchestrator` — useful when the catalog is large; less critical if the initial offer stays small
- 🔷 🚫 Do not default-offer skills 03 marked skip (grill-me, discovery, document-converter, …)
