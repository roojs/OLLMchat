# 8.5 — Drop `CallParam`; reply as `GLib.Value`

> **Do not update `docs/plans/1.0-summary.md` for this plan.**

**Status:** **PROPOSED** — Phase 1 (8.5.1) agent ✔️ consumer cut; Phase 2 ⏳. No sub-plan fences until this shape is confirmed.

**Pointer:** `docs/guide-to-writing-plans.md` — **Checklist for plans**; proposed Vala follows **`docs/coding-standards.md`**

**Builds on:** [`8.4-rpc-positional-values-and-ffi.md`](8.4-rpc-positional-values-and-ffi.md) — positional `GLib.Value` lists and `Bin.StreamValue` already exist. 8.4 left `CallParam` in place on purpose.

**Related:** [`docs/bin-rpc-protocol.md`](../bin-rpc-protocol.md) §15 (`ANY[]`), root `Response.result` object arrays. [`8.3.3-REJECTED-notification-gobject-payload.md`](8.3.3-REJECTED-notification-gobject-payload.md) — GObject `payload` on `Notification` was withdrawn; a `GLib.Value` is a different question.

---

## Purpose

- **🔷** Next cut: migrate **every** `CallParam` consumer (handlers + callers) to **`Request.args`** / `OLLMrpc.args(...)`. Delete the bags only when nothing reads `request.param`.
- **🔷** `OLLMrpc.args("s", path)` (D-Bus signature + Vala `...`) only boxes. Lease / `export` / live wire stays on Request write (`StreamValue`).
- **🔷** Later: replace **`Response.result`** (`Gee.ArrayList<GLib.Object>`) with a reply **`GLib.Value`** (and maybe `Notification`). That is **not** the next step.
- **⏳** Sub-plans: **8.5.1** = migrate inventory below + delete bags; **8.5.2** = reply `GLib.Value`. Not written until this parent is confirmed.
- **ℹ️** Infrastructure already in tree: `OLLMrpc.args`, `Request.args` / `Response.args` (rename from `values`). Phase 1 work left is the consumer cut, not more packing helpers.

**Suggested order:** migrate CallParam consumers (8.5.1) → delete bags / `Request.param` → reply `GLib.Value` (8.5.2). Can overlap remaining 8.4 FFI; 8.5.2 needs `StreamValue` live-handle / `OBJECT[]`.

## Phase 1 — migrate every `CallParam` consumer to `args`

Each method only sends what it uses (C / GIR style). Shared bags today send unused fields on every call.

**🔷** Both ends of a method move in the same cut (handler + callers). No dual-read of leftover `param`.

**🔷** After the inventory is empty: delete `CallParam` and subclasses, `Request.param`, `param_types`; `Request.register(name, target)` only.

**Default (implement, do not ask):** fields the handler already reads, in that order; D-Bus letter from the Vala type (`s` / `i` / `b` / `u` / `x` / `t` / `as` / …). Empty bag → omit `args`. Drop unused bag fields. Straight conversions are **🔷**.

## Phase 2 — `Response.result` becomes a `GLib.Value` (later)

Do **not** start this until Phase 1 inventory is empty (or explicitly split).

### Contract

- **🔷** Delete `Response.result` (`Gee.ArrayList<GLib.Object>`).
- **🔷** Reply payload is one **`GLib.Value`** via `StreamValue` (object, object list, scalar, …).
- **🔷** `Gi` stops `response.result.add(obj)`.
- **ℹ️** `Response.args` (GI return + OUT) stays unless folded.

### Open packing questions

- **💩** Property shape: `GLib.Value result` vs fold objects into `Response.args`
- **💩** GI return **and** OUT — keep `args` slots vs single `ANY[]` value
- **💩** Fold `msg` / `msg_encode` into that value, or leave for later
- **🔷** `StreamValue` must learn live-handle write + `OBJECT` in `read_array`

### Consumers (8.5.2)

- **⏳** `libocrpc/Response.vala`, `Gi.vala`, `Client.vala` HTTP `result`
- **⏳** `libocfiles` / `libochf` / tests asserting `result.size` / `result.get(0)`
- **⏳** Notification payload (same shape as reply; 8.3.3 stays withdrawn)
