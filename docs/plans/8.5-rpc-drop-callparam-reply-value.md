# 8.5 — Drop `CallParam`; reply as `GLib.Value`

> **Do not update `docs/plans/1.0-summary.md` for this plan.**

**Status:** **PROPOSED** — parent for review. No sub-plan fences until this shape is confirmed.

**Pointer:** `docs/guide-to-writing-plans.md` — **Checklist for plans**; proposed Vala follows **`docs/coding-standards.md`**

**Builds on:** [`8.4-rpc-positional-values-and-ffi.md`](8.4-rpc-positional-values-and-ffi.md) — positional `GLib.Value` lists and `Bin.StreamValue` already exist (8.4 names them `values`). 8.4 left `CallParam` in place on purpose.

**Related:** [`docs/bin-rpc-protocol.md`](../bin-rpc-protocol.md) §15 (`ANY[]`), root `Response.result` object arrays. [`8.3.3-REJECTED-notification-gobject-payload.md`](8.3.3-REJECTED-notification-gobject-payload.md) — GObject `payload` on `Notification` was withdrawn; a `GLib.Value` is a different question.

---

## Purpose

- **🔷** Phase 1 — remove the **`CallParam` object** (`Request.param`) **completely**. Call arguments are **`Request.args`** only (rename of today’s `Request.values`).
- **🔷** A top-level **`OLLMrpc.args("s", path)`** (D-Bus signature + Vala `...`) packs into that `Gee.ArrayList<GLib.Value?>`. It **only boxes**. Leasing / `export()` / live-handle wire form is the **Request write** path (`StreamValue`), not `args()`.
- **🔷** Phase 2 — replace the **`Response.result`** object array with a **`GLib.Value`** that can hold whatever the reply needs (object, object list, scalar, string, bytes, …).
- **🔷** That reply shape may also apply to **`Notification`**.
- **⏳** Sub-plans **8.5.1** (Phase 1) and **8.5.2** (Phase 2 + notification) — not written until this parent is confirmed.
- **ℹ️** 8.4 is still in flight (FFI leftovers). This parent does **not** wait on [`8.4.6`](8.4.6-rpc-ffi-leftovers.md) / [`8.4.7`](8.4.7-rpc-ffi-inout.md) for Phase 1. Phase 2 needs `StreamValue` to carry objects the way `result` does today (including live handles).

**Suggested order:** 8.4.1 (done) → **8.5.1** (can overlap remaining 8.4 FFI) → **8.5.2** (after `StreamValue` object / object-array / live-handle write).

## Current behaviour

- **ℹ️** Two argument styles on `Request`:
  - named bag — `param` (`CallParam` subclass, always present, default empty `CallParam`)
  - positional — `args` (`Gee.ArrayList<GLib.Value?>`, omitted on the wire when empty; 8.4 name was `values`)
- **ℹ️** `Request.register(name, target, param_type)` stores `param_types[target.get_type()] = param_type`. Bin dispatch does **not** read that map (the nested object carries its own alias). The map was aimed at auto-JSON hint tables in [`8.2`](8.2-full-rpc-system.md) Phase 2b.
- **ℹ️** Handlers cast: `var p = (FileParams) request.param;` then named fields.
- **ℹ️** Three reply channels on `Response`:
  - `result` — `Gee.ArrayList<GLib.Object>` (0 / 1 / N). Custom `bin_write_prop`: omit when empty; `OBJECT|0x80` array; live non-`Serializable` instances write a **lease id**, not a property dump.
  - `args` — positional `GLib.Value`s (GI return + OUT). `StreamValue.write` / `read`. (8.4 name was `values`.)
  - `msg` / `msg_encode` — string payload (`File.read` content, `File.exists` type code, vector CLI text).
- **ℹ️** `StreamValue` already encodes `OBJECT` (must be `Bin.Serializable`, property dump) and some arrays. **`read_array` does not accept `OBJECT`**. Live-handle lease encoding lives only on `Response.result`, not in `StreamValue`.
- **ℹ️** `Notification` is a grab-bag of named fields (`method`, `object_type`, `id`, `message`, progress, action, `buffer`). No positional list. [`8.3.3`](8.3.3-REJECTED-notification-gobject-payload.md) withdrew a `GLib.Object payload`.

### `CallParam` bags to delete

- **ℹ️** `libocrpc/CallParam.vala` — base class.
- **ℹ️** `libocrpc/Live/RemoteParams.vala` — `object_id`.
- **ℹ️** `libocrpc/Live/SubscribeParams.vala` — `object_id`, `name`.
- **ℹ️** `libocrpc/Live/namespace.vala` — Win32/Android stubs of those two.
- **ℹ️** `ollmfilesd/CallParam.vala` — `DaemonParams`, `ProjectParams`, `FileParams`, `FolderParams`, `VectorParams` (also compiled into `libocfiles` via meson).
- **ℹ️** `libochf/Param/Search.vala` — Hub query bag; HTTP client walks properties into a query string (`libocrpc/Client.vala` `send_http`).

## Phase 1 — drop `CallParam`, use `args`

### 1. `OLLMrpc.args` — D-Bus signature + Vala varargs

- **🔷** `✔️` Namespace function, not a method on `Request`. First argument is a **D-Bus type signature** (same letters as GVariant / `GLib.VariantType`). The rest is Vala `...`. `va_list` + `GLib.VariantType.string_scan` walks complete types; each `va_arg` is boxed with the matching `set_*`.
- **🔷** Callers write:
  - `new Request() { method = "RPC-File.read", args = OLLMrpc.args("s", this.path) }`
  - `OLLMrpc.args("is", protocol, client)` for `RPC-Daemon.hello`
- **🔷** Letters (concatenated, no spaces — D-Bus style, not `"n n n"`):
  - `s` string, `b` bool, `y` byte, `n` int16, `q` uint16, `i` int32, `u` uint32, `x` int64, `t` uint64, `d` double
  - `o` GObject (`set_object` as-is; D-Bus `o` is object path, here it is an instance)
  - `g` signature string, `h` unix fd (int)
  - `as` `string[]`, `ay` `GLib.Bytes`, `v` `GLib.Variant`
- **🔷** Unknown or invalid signature is **fatal** (`GLib.error`). Do not skip, drop, or ask the caller to wrap by hand.
- **🔷** `args` **only boxes**. No lease ids, no `export()`, no `Bin.Serializable` check. Request write / `StreamValue` owns the wire form.
- **ℹ️** Landed: `libocrpc/namespace.vala`. Smoke: `tests/rpc/values-test.vala` (`sibt`, `o`, `as`).
- **🚫** `params GLib.Value[]` — that is an array copy, not varargs.

### 2–8. Rest of Phase 1

- **🔷** `✔️` **2.** Rename `Request.values` / `Response.values` → `args` (wire name too). `Gi.vala`, tests, protocol §15.
- **🔷** `⏳` **3.** Delete `CallParam` / `Request.param` / `param_types`. `Request.register(name, target)` only.
- **🔷** `⏳` **4.** libocrpc Live (`Remote` / `Subscribe`) + tests (`live-handles-test`, `proxies-test`, `subscribe-test`).
- **🔷** `⏳` **5.** ollmfilesd handlers + `Application.register` + delete `ollmfilesd/CallParam.vala`.
- **🔷** `⏳` **6.** libocfiles callers (`new Request() { args = OLLMrpc.args("s", ...) }`).
- **🔷** `⏳` **7.** HTTP / libochf (`send_http` query walk — packing choice still **💩**).
- **🔷** `⏳` **8.** meson / valadoc / `docs/bin-rpc-protocol.md`.

### Contract

- **🔷** Delete `CallParam` and every subclass listed above.
- **🔷** Delete `Request.param`.
- **🔷** Rename `Request.values` → **`Request.args`**. Same type (`Gee.ArrayList<GLib.Value?>`). Same `ANY[]` codec. Wire property name becomes `args`.
- **🔷** Rename `Response.values` → **`Response.args`** in the same cut (one name on request and reply).
- **🔷** `Request.register` loses `param_type` — `register(name, target)` only. Delete `param_types`.
- **🔷** Callers put arguments on `Request.args` in a **documented per-method order** (GIR order on the typelib path; hand handlers get an explicit list).
- **🔷** No dual read of a leftover `param` property. Both ends move together.
- **🔷** Empty `args` stays omitted on the wire (same as empty `values` today).

### Why per-method, not “bag fields in property order”

- **ℹ️** One shared `FileParams` is sent on every `RPC-File.*` call, including unused fields (`File.read` still carries `content`, `unix_mode`, …). Bin does not skip scalar defaults.
- **🔷** After the cut, each method only sends what it uses, trailing defaults omitted (C / GIR style):
  - `RPC-Daemon.hello` — `protocol` (int), `client` (string)
  - `RPC-File.read` — `OLLMrpc.args("s", path)`
  - `RPC-File.write` — `path`, `content`, plus the write-only fields that method actually reads
  - `RPC-Live-Remote.ref` / `unref` — **💩** `Request.lease_id` (already on the request for GI) rather than `args.get(0)` as `uint64`; `RemoteParams` goes away either way
  - `RPC-Live-Subscribe.signal` — lease + `name` (`lease_id` + `args.get(0)` string, or both in `args`)

### Handler shape (intent, not a fence)

- **ℹ️** Today: `var p = (FileParams) request.param;` then `p.path`.
- **🔷** After: `request.args.get(0).get_string()` (path), index per that method’s list.
- **ℹ️** `call_*` signals stay; they already receive `Request`. The only new function is **`OLLMrpc.args`**.

### HTTP (`Client.send_http` + `OLLMhf.Param.Search`)

- **ℹ️** Hub search is named query fields (`search`, `filter`, `limit`, …), not positional RPC. `send_http` iterates `request.param` properties into `?k=v`.
- **💩** After `CallParam` is gone, pick one:
  - any `GLib.Object` in `args.get(0)` — walk its properties into the query string (Search becomes a plain GObject, not a `CallParam`)
  - keep a tiny HTTP-only query object that is **not** `CallParam` / **not** used on the bin socket
- **🚫** Do not keep `Request.param` “just for HTTP”.

### Wire / JSON

- **🔷** Bin `Request` no longer has a `param` member. The positional list’s wire name is **`args`** (not `values`). JSON example becomes `"args":[…]` instead of `"param":{…}` / `"values":[…]`.
- **ℹ️** [`8.2`](8.2-full-rpc-system.md) Phase 2b **param hint table** is largely unneeded: `args` is `ANY[]` with per-element types. Result-element hints stay a Phase 2 (8.5.2 / 8.2) question until `result` is a `GLib.Value`.
- **💩** Protocol version / `Daemon.protocol` bump — 8.4 added `values` with **no** bump. Removing `param` **and** renaming `values` → `args` is a breaking cut. Coordinated same-commit client+daemon (like other 8.x cuts) vs an explicit hello bump.

### Consumers to migrate in 8.5.1

- **⏳** `libocrpc` — `CallParam` (delete), `Client` docs + HTTP query walk, Live `Remote` / `Subscribe`, tests that still use `param`.
- **ℹ️** `libocrpc` already: `OLLMrpc.args` in `namespace.vala`, `Request.args` / `Response.args` (wire name `args`), `Gi.vala` reads `request.args` / `response.args`.
- **⏳** `ollmfilesd` — `CallParam.vala` (delete), every `request.param` cast, `Application` `Request.register` third argument, `Daemon.rpc_register` of `*Params` aliases.
- **⏳** `libocfiles` — every `new Request() { param = new *Params() }`.
- **⏳** `libochf` / `examples/oc-hf.vala` — `Param.Search` + HTTP `param`.
- **⏳** meson — drop `CallParam.vala` from `libocrpc`, `ollmfilesd`, `libocfiles`, valadoc lists. The dual-namespace GIR workaround that exists **because** `CallParam` is `OLLMfilesd` may simplify.
- **ℹ️** `docs/bin-rpc-protocol.md` — drop `CallParam`-only traffic wording; rename §15 `Request.values` / `Response.values` → `args`.

## Phase 2 — `Response.result` becomes a `GLib.Value`

### Contract

- **🔷** Delete `Response.result` (`Gee.ArrayList<GLib.Object>`).
- **🔷** The reply payload is a **`GLib.Value`**, encoded with `StreamValue` (one type byte + payload). That value can be:
  - unset / `G_TYPE_INVALID` — no payload (omit on the wire, same as empty `result` today)
  - one `OBJECT` (including live lease)
  - an object array (`OBJECT|0x80`)
  - a scalar, string, `string[]`, bytes, numeric slab, … anything `StreamValue` already knows
- **🔷** `Gi` stops `response.result.add(obj)` — it puts the GObject (or list) in that `GLib.Value`.
- **ℹ️** `Response.args` (GI return + OUT list, today’s `values`) stays in this phase unless the next bullet is promoted.

### Open packing questions

- **💩** Property shape:
  - `public GLib.Value result { get; set; }` — matches “one `GLib.Value`” wording; Vala `GParamSpecValue`; unset = invalid type
  - drop `result` and put objects into existing `Response.args` (`args.get(0)` is the object or `OBJECT[]`) — less new API, but the reply is a list again
- **💩** GI methods with a return **and** OUT args — keep `Response.args` as the extra slots, or make the single `GLib.Value` itself `ANY[]`.
- **💩** Fold `msg` / `msg_encode` into the same `GLib.Value` (`STRING` vs `BYTES`) in this phase, or leave `msg` until a later cleanup. `File.read` today is **both** a `File` in `result` **and** content in `msg`.
- **🔷** `StreamValue.write` for `OBJECT` must learn the **live-handle** path `Response.result` already has (lease id + `TOKEN_END` when `live_handles` and not `Serializable`). Today `StreamValue` throws if the object is not `Serializable`.
- **🔷** `StreamValue.read_array` must accept `OBJECT` (homogeneous object lists). Today it throws for that tag. That is also the wire form for `GLib.List` / `SList` / `HashTable` GObject collections (`Gi.scalar_list` / `scalar_hash`).

### Consumers to migrate in 8.5.2

- **⏳** `libocrpc/Response.vala` — delete `result` encode/decode; one `StreamValue` slot (or fold into `args`).
- **⏳** `libocrpc/Gi.vala` — `result.add` / `scalar_list` / `scalar_hash`.
- **⏳** `libocrpc/Client.vala` HTTP — `response.result.add(obj)` after JSON decode via `result_type`.
- **⏳** `libocfiles` — `(Gee.ArrayList<File>) response.result`, `result.get(0)`, `result.size`.
- **⏳** `libochf` / examples — `resp.result[0]` hub models.
- **⏳** tests — `gi-test`, HTTP tests, anything asserting `result.size`.
- **ℹ️** `Gi.scalar_list` / `scalar_hash` already exist and fill `Response.result`. 8.5.2 retargets them at the reply `GLib.Value` (`OBJECT[]`). [`8.4.6`](8.4.6-rpc-ffi-leftovers.md) other leftovers (float slabs, narrow ints, …) stay in 8.4.6.

### Notification

- **🔷** Same idea as the reply: a typed payload, not a new GObject property (8.3.3 stays withdrawn).
- **💩** Add `Notification.args` (`ANY[]`, same codec as `Request.args`) **or** one `GLib.Value` — pick the same shape as `Response` so callers learn one pattern.
- **ℹ️** Keep `method` + `id` / `object_type` for live references (8.3.1 `export()` + handle). Subscribe `notify::` currently stuffs the property into `message` as a string; a `GLib.Value` can carry the real type.
- **💩** Whether banner fields (`progress_*`, `action`, `action_label`) stay named or move into `args` — not required to start Phase 2; ollmfilesd / `ActivityBanner` use those names today.
- **⏳** Touch: `libocrpc/Notification.vala`, Live `Subscribe` / `Subscription`, `ollmfilesd` broadcasts, `ollmapp/ActivityBanner.vala`.
